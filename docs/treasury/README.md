# 侵吞国库

## 留证规则

计谋当场败露判定及公开罪行后果沿用原版。未败露的成功、失败、抹记录与失效收尾统一按最终隐秘性判断是否留下侵吞秘密；概率由 `tca_treasury_secret_chance_value` 集中维护，最低15%，最高100%。只有实际侵吞金额大于零、实施者存活且双方仍有国库才新建秘密，金额记录沿用原版；本轮没有留下秘密也不会清除旧秘密。

结算标记保存在计谋自身，正常收尾与失效只判定一次。当场败露收尾也写标记，防止后续失效补建秘密。抹记录是尝试善后，不能免除最低风险。

## 接口与兼容

正式入口为 `common/scripted_effects/tca_treasury_secret_effects.txt`，作用域为仍存在的计谋，TARGET为原版该次结算的受害人物。计谋对象与两个收尾事件中的秘密创建代码均为内联，没有原生局部追加接口，因此采用不同文件名覆盖三个对象；原版基线、必要性与本地化登记统一见 `tools/upstream_overrides.json`。修改同名对象的模组需合并，未覆盖整份原版文件。

## 验证

原生登记模块 `treasury_secret` 使用仅限debug测试的计谋夹具，以原版上下限字段固定100与0隐秘性，验证风险下限、零赃款、秘密金额、结算防重及成功／失败结果事件。使用独立可丢弃观察者测试局，运行方式见[测试入口](../testing/README.md)。

专用计谋夹具不证明原版计谋modifier的刷新时机，也不能替代完整自然路径验收。

抹记录选项的真实玩家显示与点击、自然阶段触发、资格失效自然回调及保存重载需专项验收；直接调用共享入口不能替代这些路径。原版常规隐秘性上限为95，100隐秘性的选项仍保留原版显示条件，但其效果同样调用留证入口。
