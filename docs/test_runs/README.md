# 逐轮验收记录

本目录保存每一轮引擎验收的证据，一轮一个文件。框架契约与运行方式仍以[统一测试文档](../mod_tests.md)为准，失效方案和早期结果归档在[历史记录](../history/mod_tests_history.md)。

## 何时新增

一次实质变更、修复或复测完成后新增一个文件。同一轮修复如果经历“失败复现 → 中间失败 → 修复通过”多次运行，放在同一文件内按时间顺序列出，不拆成多个文件；不同主题、不同日期分别开文件。

只写文件、不改旧文件：历史结果保持原文，后续复测追加新文件并互相链接，不用新结果覆盖旧失败记录。仅修正笔误、失效链接或失效路径时可原地编辑。

文件内容反映当轮源码与当时的结论，不随后续修改更新；标题中的主题和数值只代表该轮，当前实现、数值与状态以模块文档为准。

## 命名

`YYYY-MM-DD-<主题>.md`，主题用简短英文小写与连字符，例如 `2026-10-21-exam-family-notification.md`。文件名按字典序即时间顺序，不另建手工维护的总索引。

## 模板

```markdown
# <主题>（YYYY-MM-DD）

- 入口：`python3 tools/run_game_tests.py --seed 1538798675`
- 运行：`run-xxxxxxxx`，CK3 <版本>，独立1066观察者局，仅冻结主模组与CLI适配
- 结果：<N> BEGIN／<N> PASS／<M> CHECK_PASS，零失败或未执行
- 核对：observer、summary、verification_exit=0、runner_exit=0，同次 error.log 无 tca_ 记录
- 失败到通过：<旧实现的失败断言> → <修复后通过>
- 未覆盖：<界面渲染、保存重载、自然AI等>

实现与验收步骤见[<模块文档>](../<module>.md#<anchor>)。
```

实际写作以原文证据为重，可省略不适用项；不要为了套模板删减运行ID、计数、退出码和日志核对结论。

## 记录内容

至少包含：执行入口与参数、CK3 版本与场景、运行 ID、用例／断言计数、通过或失败明细、观察者与汇总状态、退出码、日志核对结论、未覆盖范围，以及对应实现文档的链接。

## 与模块文档的分工

- 本目录：拥有运行证据，保留原始计数、ID、失败记录和当时的判断。
- 模块文档：拥有设计、当前实现、当前状态、最近验证指针和未覆盖事项，不复制运行明细。
- [统一测试文档](../mod_tests.md)：拥有框架结构、登记规则、运行入口和通过标准，不保存逐轮结果。
