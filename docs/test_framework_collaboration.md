# 测试框架协作改造

## 目标与约束

默认完整回归一次启动，同局串行执行；可选择即时／延迟单项、一个或多个模块，显式按模块隔离才分别建局。原生隐藏事件仍是业务测试源，不生成测试或在 Python 模拟玩法。模块维护原生用例登记，工具读取、校验并形成冻结的运行计划。

## 实施计划

使用 writing-plans、executing-plans 与 test-driven-development，按已批准方案在当前工作区实施；不提交、不推送，不覆盖其他改动。

- [x] 原生登记与派发：新增 `tca_test_modules_*_effects.txt` 模块登记，通用原生派发替代全局阶段链；保持现有用例和断言集合。先增加登记完整性、即时选择与去重回归。
- [x] 选择与验收：`tools/testing/catalog.py` 读取原生登记；`--list`、重复 `--suite`／`--case` 合并选择；冻结 `selection.json`，验收严格核对预期范围和结果。
- [x] 封存与排队：封存验收工具依赖、输入摘要及版本信息，检测复制期间变化；同机文件锁等待，等待前冻结全部输入；不操作已有游戏进程。
- [x] 可选隔离：`--isolate suite` 将所选模块拆为独立子运行，统一任务 ID 和总结果；中断或缺失子结果不得通过。
- [x] 文档与验证（执行并如实记录失败边界）：更新 README、CLI 及维护文档；完整 Python、覆盖检查、即时／延迟选择、多模块及隔离引擎运行和默认完整引擎回归。

## 关键接口与边界

- 原生 `tca_test_visit_case_effect = { EVENT = … CASE = … DELAYED = yes/no }` 负责计数、选择、派发与清理；模块只登记，不复写业务逻辑。
- `catalog(root)` 返回模块、入口、日志标识、即时／延迟及断言数；`select_cases(root, suites, cases)` 返回按原生顺序去重的执行计划。未知选择或登记不一致直接拒绝。
- `prepare_run` 先复制并验证输入，再从冻结登记选择、配置适配并封存；`run_game` 仅使用冻结验收工具。配置选择只写适配，不改正式测试。
- 断言失败且环境有效时继续；环境损坏中止，同次尚未开始的用例标为未执行。部分结果不可称完整回归，隔离结果不可称同局回归。
- 默认运行锁跨输出根目录生效；等待不计入游戏执行超时。锁在进程退出及结果收集后释放。
- 外部游戏安装、Steam、DLC 仍非封闭依赖；版本、种子和执行参数记录在运行证据中。
