# 北方边疆当前工作与验收

本页只维护当前剩余工作和取舍。规则分别由[局势与有限战争](design.md)、[通用响应／收复](war_response.md)及[双边和约](treaties.md)维护；启用范围见[模块入口](README.md)，通过与未解决问题见[验证页](verification.md)。已完成的施工步骤不继续作为未来任务。

## 兼容与行为缺口

1. **原版召唤参战的和约责任**：`frontier_influence_war_interaction`由地方官使用`influence_war_cb`开战，但现有和约只识别君主本人和自有中央来源标记，尚未将此原版入口识别为中央授意。应补准确归责，保留原版互动，不重新开发中央出兵系统。该CB也不在16类通用响应白名单内；是否扩大响应范围另行决定，不能把全CB和约监测当作已经提供全CB防御响应。
2. **和约信息与选战判断**：自定义开战已有费用、战果与原版停战提示，但和约责任、预计支援的完整玩家预览尚未接入。季度AI没有读取和约责任，仅在实际开战后由独立和约处理；后续须确定提示和评估口径，不能写成AI已经主动考虑全部条约代价。
3. **未解决验证波动**：旧罢兵的延迟罢免合取断言，以及已记录的收复接续波动，按验证页保留实际失败和复现入口。后来的单次通过不证明原因已解决；维护时只对实际相关路径排查，不重复全量掩盖问题。

## 玩家流程与开放前验收

- 自定义战争：原生人物互动的真实头衔选择、四种战争选项、费用／停战／战果动态提示、土地分配与罢兵书信的完整操作。入口继续保持调试授权，不以源码已实现自动开放。
- 共享响应与收复：书信阻塞与回复、右侧消息／上方通知的实际位置、复杂多级军队动员及到达前线。原始AI书信、实际参战和拥有军力各有证据，不能相互替代。
- 和约：外交紧凑／展开条目、第三国只读查看、提案与拒绝、修改和约、补缴／拒付／免债、和平解除及毁约确认。核心事务和原生战争测试已有定向证据；实际显示与点击尚未验收。
- 整体局势：当前无子区域切换界面的显示、参与者与动态称谓、统一结束决议措辞。旧自有窗口人工通过不覆盖这些新入口。

以上按具体功能选择最小充分验收，不要求每次文档修改或提交重启游戏，也不把原版机制的全面重测列为固定门槛。

## 暂缓与取消

- **取消自建中央命边臣出兵（旧P5）**：原版已有“召唤参战”，最高领主也能直接宣战。不新增中央金币资助、拒诏处分、命令期限和冷却系统，不额外限制最高领主亲自开战。保留原生互动及必要兼容。
- **暂缓和平倾向改写（旧C3）**：不将未到的承诺援军额外计入原版议和，不覆盖白和平、投降与自动接受互动。以后重启需重新核对接口及实际问题。
- **不再推进旧自有宣战窗口与双区域玩法**：其源码和旧验收只作原型范围解释，当前采用整体局势与原生互动。
- **其他政体的内部处分、额外防御拒绝处罚与参战功绩**：尚未决定，不因天朝处罚或当前防御书信存在而自动推广。和约的国家违约后果与天朝内部抗命处分分别维护。

## 维护与验证顺序

先核对所属源码和原版依据，再处理具体缺口；共享接口变动只扩展实际受影响消费者。定向原生测试优先显式`--parallel 4`，按独立WORLD隔离，不使用正常游玩存档。保留真实原始回调、AI书信、持久记录与保存重载，不能全部由worker调用替代。

仅文档整理检查链接、锚点、过时断言和差异，不新增业务测试、不启动游戏。测试登记或覆盖改动才按对应规范运行检查；全量及串并行双跑不是收口固定步骤。

旧P0—P12和A—F编号保留在历史代码、测试标识与验证标题中便于追溯，不再表示全部待开发或严格前后依赖。完整旧路线可从固定版本`db77d7c`读取；重要取舍和仍未解决的失败已经保留在现行规则与验证页，不另建一套逐轮历史手册。
