# 北疆验证与当前边界

本页维护[北方边疆局势](README.md)及其共享战争、和约模块的可复现验收入口和未解决问题。当前规则分别由[玩法设计](design.md)、[通用响应与收复](war_response.md)、[双边和约](treaties.md)维护；实施范围见[计划](plan.md)。本次整理只核对文档、源码与测试登记，没有重新运行游戏。下述既有结果对应各次冻结源码，不是当前工作区重新验收，也不能扩展为完整玩家流程或长期自然AI已通过。

## 当前范围与证据使用

- 整体北疆局势、三组参与者、三阶段修正、正式催化、1066自动生命周期与统一结束已有实现及对应定向用例。
- 四类自定义有限战争及季度出兵仍要求debug显式授权，正常宣战入口关闭。土地分配、逐县功绩、天朝罢兵问责是这些战争的消费者，不因其已有测试而开放普通宣战。
- 16个原版白名单CB的通用防御响应与特殊收复正常启用，不依赖北疆、debug或自定义战争授权。独立双边和约及外交入口正常启用，GUI仍未完成验收。
- 用户已取消P5自建“中央命边臣出兵”。保留原版召唤参战，不额外限制最高领主直接宣战；原版`influence_war_cb`的中央授意识别仍是待修兼容缺口，见[和约边界](#双边和约与岁币)。

普通旧运行计数、夹具迭代和开发过程由固定Git版本`db77d7c`中的本页追溯。双区域及自有宣战窗口属于历史原型，不是当前任务。保留在本页的旧结果只说明其明确覆盖的能力、重要取舍或未解决失败；没有共享原始产物的结果仅作历史线索，复核应使用随库用例，不能把旧PASS当作当前验收凭据。

## 可复现的原生验收

[测试登记](../../common/scripted_effects/tests/modules/tca_test_modules_frontier_probe_effects.txt)是事件、独立WORLD、GROUP及独占属性的正式入口；[运行说明](../testing/README.md)维护工具要求。按本次改动选择最小相关范围，先列出计划，例如：

```sh
python3 tools/run_game_tests.py --suite frontier --list
python3 tools/run_game_tests.py --case tca_frontier_support_test.1 --parallel 4 --timeout 600
```

本页列出的独立用例不进入普通全量或游戏内全组派发；显式选择后，CLI按WORLD强制新建可丢弃局。同WORLD原版CB用例保留各自框架上下文。K=4不证明独占项实际并发，分局通过也不证明同局或普通全量通过。不得投递到正常游玩存档。

核对同次冻结计划、`terminal.json`、`result.txt`、`debug.log`的`TCA_TEST`及`error.log`；超时、前置不满足、缺断言、无观察者确认或相关引擎错误均不能算通过。保存重载还须检查`reload_evidence.json`、两次原生进程的观察者确认及检查点载入证据。不能只凭恢复变量、GetPlayer ID或断言PASS证明真实载入和玩家控制。

检查点GUI只在对应WORLD明确准备时工作：保存阶段先更新原生状态，再保存；恢复阶段执行原生`observe`并恢复速度，不重复开战或重置计时。七日待援检查点须降速并在保存时暂停，确认恢复后仍保留原第六日未到、第八日已加入的时间边界；只定义widget而未在`gui/scripted_widgets/`登记，不构成有效检查点。

文档整理检查相对链接、锚点及差异即可；测试登记变动才运行并行登记检查，覆盖对象变动才运行上游检查，不为本页整理机械重跑游戏。

### county_modifier作用范围探针

`tca_frontier_modifier_probe_test.1`在本机1.20.1.2以独立Situation和控制力增长修正，比较区内／区外直辖、封臣及外国县；切组、真实迁都、显式移除手动参与者及结束后读取原生数值。既有证据表明指定组和`all`均按区域裁剪参与者直辖，区外直辖不承接；切组最终只保留新组效果，显式退出最终清理。

这不是即时同步保证：名单先变而县数值暂留旧值，最终以45日为等待上限，迁都就绪后另留一周稳定本底；该上限不是精确缓存周期。仅删除私有资格flag后等45日没有自然退出，不能写成“资格变化会自动清理”，也不能由此推断正式身份都要接管。手动候选须配对`remove_manual_participant`；有地正式候选交原生分组，无地官署仅补候选。

只覆盖该版本、控制力键及上述样本，不覆盖全部正式身份、无地官署、显示、保存重载或经济军事底层行为。旧较长等待曾出现原版`dynastic_cycle_yearly_pulse`缺失`var:situation`错误，未在本探针修复，不作跨年兼容证据。

## 正式三阶段修正

数值及字段由[阶段设计](design.md#阶段负担与动员收益)和[原版接口](ai.md#局势参与组与阶段修正)维护。`tca_frontier_phase_test.1`在专属WORLD比较原生参考修正与正式三阶段收入、名单、结束恢复；固定财政总管与无效果测试任务，隔离AI更换任务、招募和建设。县税及收入有缓存，须跨月取样，不能用两日相同读数证明相同或清理。

既有自动断言覆盖收入校准、三阶段对照、名单及恢复。同轮原生日志另人工核对区内税收明细、区外排除、私人／头衔军报价、驻军及征召；日志读数不升级为自动军事断言，报价不等于实际扣款。境内征召尚无稳定本底的精确隔离结论。相关组后来配置与境内组同档区域县修正，仅做已确认字段、数值与叠加关系的静态核对，未为此重跑引擎。

不要求重验原版完整伤害与付款机制；实际战斗中的防御方优势传递、完整玩家显示、全部正式身份失效与改隶、无地官署军队及长期平衡，没有相应专项证据时不得宣称已通过。

## C阶段防御承诺与延迟加入

`tca_frontier_support_test.1`使用正式开战及支援入口，检查受威胁中间领主、上级不重复入邻近、同国限制、去重、评分对照、双战争隔离、真实延迟、提前结束、死亡／改隶退出、结束快照与回收。保存发生于已承诺未加入且另一战已结束时，恢复须续接同一story与原限时变量。既有通用化定向记录包含实际保存重载；主防守者主动独立导致的取消不得被后续白和平改写。
