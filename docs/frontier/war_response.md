# 通用争地战争响应与失地收复

## 状态与维护边界

本文是响应与收复通用化的设计及维护依据，当前共享层已完成源码接入与定向引擎验收。共享入口接入下列原版白名单与原四类自定义边境战争；继承、结算前快照、直接夺地及改隶型归还、128县精确收复均有对应验证。具体原版分支、保存重载及人工边界由[验证页](verification.md#通用争地战争响应与收复实施状态)维护，既有C/D证据不自动扩大为未执行的组合或长期平衡结论。

通用层负责战争适配、受影响地区、支援承诺、延迟加入、失地与收复；北疆局势继续负责地域环境、阶段和催化。四类自定义有限战争仍限debug授权，使用自己的宣战资格、目标、计分和战果，作为共享响应层的消费者；普通游戏的16类原版白名单不受该debug开关限制。本次不把原版战争改成有限战争，不改主防守者，不让已参战者退出后重新等待，不改原版议和规则。自定义有限战争是否脱离北疆开放，是另一个任务。

本页拥有通用化范围和收复资格；[设计页](design.md#响应与议和)继续维护沿用的响应时间、AI评分、通知及书信参数，不复制数值表。现有`tca_frontier_support_*`与`tca_frontier_recovery_*`标识已作为共享入口使用，不能因名称含frontier就重新附加局势限制。

## 已确定的范围

只接入对外争地战争：开战时双方最高领主不同。同国内部争地、继承与争位、自由权、独立、废黜等战争不纳入。白名单按具体CB判断，不能只根据存在目标头衔或CB分组推断资格。

第一批已接入的原版白名单如下；实际分支覆盖以验证页为准：

- 普通征服：`county_conquest_cb`、`duchy_conquest_cb`、`ducal_conquest_cb`。
- 法理争夺：`individual_county_de_jure_cb`、`individual_duchy_de_jure_cb`、`de_jure_cb`。
- 天朝夺地：`china_seize_county_cb`、`china_hegemon_seize_county_cb`、`china_seize_duchy_cb`、`china_hegemon_seize_duchy_cb`。
- 行政扩张：`expansion_cb`、`duchy_expansion_cb`、`naval_expansion_cb`、`naval_duchy_expansion_cb`。
- 游牧征服：`nomadic_conquest_cb`、`nomadic_conquest_duchy_cb`。

海上宣战资格沿用原CB；防守响应中的邻近仍按目标周围陆地邻县，不因海军扩张改成跨海扩散。

领土宣称`claim_cb`与普通圣战`minor_religious_war`、`religious_war`、`major_religious_war`是后续候选，不在第一批：前者须区分地方领土与王国／帝国争位、第三方受益人；后者须处理原生同信仰援助去重与不同战果。大型入侵、冒险者战争、大圣战、天朝整合／再统一和大征伐暂缓。强迫臣服、朝贡、宝物、纯劫掠等原版CB不纳入本批。

现有四类自定义边境战争继续接共享响应，包括已有劫掠战争；这是保留现有消费者，不代表将原版纯劫掠加入白名单。没有实际失地的战争不触发收复。

## 战争适配与受影响地区

每类适配须核对本机原版CB、它调用的结算效果、目标选择与结束回调顺序。开战时输出本场实际可能受战果影响的县集合；公国或更高目标必须与防守方实际领土及该CB的战果范围求交，不把整个法理区域或全国一律算入。

目标集合只含实土县，不把县级无地官署头衔当作土地；提刑、通判等地方主官仍按正式身份与辖区进入响应候选。目标集合是响应的地理依据；战后实际失地另行核对，不能把所有目标都记成已经失去。多目标按县去重；原生CB若有当前通用适配无法准确表达的结算分支，应补准确适配或明确报告未支持，不能扩大或截断目标冒充完成。

每战在结算前保有足以恢复归属的记录：目标县、原持有人、原直属领主、战前国家标识、必要政体，以及主战双方、主防守者独立身份、真实上级链、各人承诺与参战状态。开战快照与结算前状态应分开：战争期间合法继承、转封不能被误算成敌方夺地，也不能因为结算后才取样而丢失原归属。受援方与救援者的承诺继承按下节处理，记录须能识别原人物与承接者，并保留原到期日及参战状态。当前快照、继承接口与国家续接约定见[共享接口](#当前共享接口)，不将人物引用等同于永久国家身份。

## 通用防御响应

复用现有一战一记录、每人一响应行，不建立人物单一待援战争指针。

- 受影响者：实际目标县的相关领主；已登记无地地方主官按正式身份和绑定辖区识别，不因无实土漏掉提刑、通判。不能只凭所在地或最高领主的全国辖域入选。
- 上级：主防守者真实领主链；上级不重复列为邻近。主防守者为最高领主时，此类自然为空，其余两类仍正常工作。
- 邻近者：目标集合之外的一层陆地邻县，属于防守方同一国家，候选本人直辖或封臣辖地涉及该邻县；不递归向外扩散。

候选去重，主防守者不邀请自己，原已参战者不重复邀请；原生盟友、同信仰援助等自行加入后须取消重复待援任务。接受、拒绝、延迟、通知及AI初值沿用现有规则。这里只延迟模组额外邀请的支援，不干预原生参战者。

正式加入前重查战争、人物、国家关系、敌我立场和身份。受援方死亡、由继承人接手仍在继续的原战争时，已有救援承诺继续有效；救援者死亡时，其承诺也随相关领地或官职的继承转由承接者履行。双方正常继承均不重新邀请或要求再次接受，不重置承诺日期、预计到达日和剩余等待时间，也不重新按继承人的爵位或领主关系层数计算延迟。已参战状态须续接，不能因继承重新变成待援，也不能使原已参战的承诺取得未参战牵头资格。

承诺只沿相关战争、领地或官职的实际继承关系接续，不复制给所有继承人；承接者仍须通过国家关系、敌我立场与身份核验。没有有效承接者、非继承造成的改隶、其他资格失效或战争结束时停止旧任务。普通战争支援和收复战争支援均沿用这项继承规则，并分别保留各自原有到期日，不重新统一成一个时长。原生战争已因死亡失效时，不另建战争延续承诺。

## 特殊收复的入口

收复是未兑现防御承诺的延续，CK3中仍以独立进攻战争表示。以下条件须同时满足：

1. 原战争属于已接入范围，进攻方胜利且战果确实使土地离开战前防守国家。
2. 原主防守者不是最高领主。最高领主作为主防守者战败不触发特殊收复，也不交由封臣绕过；以后仍可正常宣战夺回。
3. 至少一位真实上级曾接受本战救援，原战争结束时承诺仍有效，而且尚未正式加入原战争。

“尚未到达”以尚未加入战争为准，不看军队位置。已经加入但军队未抵前线、加入后一同战败、拒绝、未承诺或承诺已失效者，均无本条牵头资格。此限制针对牵头，不等于禁止原参战者应邀参加新的收复战争。

结束时按战果执行前的有效承诺与参战状态冻结合格上级，再清理旧任务；最高合格上级优先，按真实链向下处理，沿用现有四政体拒绝约束。已参战上级不因爵位高而占据牵头位置。本次战果造成原主防守者或失地原主带地改隶、与旧上级断开关系，不因此取消已经冻结的收复资格；后来主动改隶等失效变化另行排除。接受之前再次核对有效身份、政治关系、失地和敌方国家；正常继承按上述承诺继承规则续接，其他失效不随意改派人选。

原参与者及原已承诺者按现有规则重新选择参加收复，邻近者不能凭参与取得土地归属权。旧承诺不自动变成新战争参战，也不再广泛召集一圈从未承诺或参战的人。

## 失地、改隶与归还

核心是土地是否离开战前国家，而非县持有人是否改变。必须分别支持：

- 土地直接转给进攻者或其战果受益人；
- 原领主保留县，但连同土地被转入敌方国家。

第二类是合法的失地路径，不能被旧代码“原主进入外国即取消”的规则一概排除。必须区分原战争造成的改隶与后来主动投靠第三国等失效变化。

收复只处理原战争实际造成、且当前仍有效的失地。直接夺地按原归属恢复；带地改隶按原领主及随其一同转属的封臣、土地核对归还范围：

- 没有本次有效失地之外的额外土地时，连同原封臣恢复相应隶属，保留合法持县者。
- 原封臣已拥有额外土地、连人恢复隶属会带回无关土地时，不把这个封臣带回；只夺回本次仍有效的失地，交给收复战争领袖。原封臣保留敌国身份与额外土地。这是保留原持县者原则的明确例外，不因这项额外土地取消整组特殊收复。

发起收复前和胜利归还时均重查额外土地与实际失地，只处理本次仍有效的目标，不扩大到原封臣的整个领地。恢复原持有人、直属关系、基层领主及政体时复用现有可行事务；改交收复战争领袖的分支须分别证明目标县转移、基层附属关系和原封臣额外领土不受波及。

承诺继承与失地受领者分别处理：战争期间合法继承后的持有人按结算前快照记录；失地后原主死亡，仍不自动为其失地另换受领者，不能把承诺继承当作重新指定全部失地受领者的依据。其余保守边界沿用：转入无关第三国不自动向第三国追讨；部分目标失效只保留可准确处理的目标，全部失效则取消。原征服者与实际受益人分离时按[共享接口](#当前共享接口)核对敌方主体和全部目标归属，不无条件向原进攻者追地。

原版战果与分封流程保持原样，不接入自定义有限战争新增的战后土地去向选择。

## 停战、成本与防止重复

已确认：特殊收复豁免牵头者对本次收复敌方的停战限制及撕约惩罚，因为它承接此前的防御承诺。豁免只能发生在正式收复事务内，不解除其他宣战的停战，不删除既有停战，不给人物留下长期免罚能力。

`tca_fd_declaration_effect`在本次原生`on_declared_war`前临时添加`allowed_war_declaration_sans_truce_penalties`，回调后仅清理由本事务新增的flag，保留人物原已有标记及既有停战。不能因有此flag就宣称所有原版CB适配已验证。

沿用现有收复成本、参与延迟、结束停战和不奖励普通扩张功绩的规则，见[追讨参数](design.md#追讨决定与衔接)。默认每场原战争最多成功建立一次特殊收复战争，拒绝递级不算新战争；收复本身不再触发特殊收复。后者是沿用已有防递归约束，非新增无限报复链。

## 接入与实现约束

通用入口使用原版战争、继承、加入与死亡回调的跨文件二级子on_action追加，不覆盖原版整文件或各个CB定义。已实测`on_war_started`在转地前派发，`on_war_won_attacker`在原版战果后、`end_war`返回前执行；原生`on_vassal_change`只有旧直属领主，缺少本次战争及转属原因，不能据此把同日自愿改隶认作战果。

为在真实战果前取样，仅覆盖小型共用效果`show_pow_release_message_effect`，保留原内容并在末尾调用`tca_ws_prepare_resolution_effect`。本机16个白名单CB的胜利事务均先调用该效果，之后才转地；效果原生查得的`scope:war`可用于定位唯一记录。通用胜方回调随后比较实际县归属。该小型效果及16个调用端已分别登记覆盖／依赖与初始审阅基线；升级须审阅调用顺序，不能自动刷新基线。理由与兼容范围归[上游登记](../../tools/upstream_overrides.json)维护。此处的快照不接管或推迟原版分封。

共享层不得依赖北疆Situation存在、北疆参与者或北疆地理区域；这些限制保留在自定义有限战争自己的资格和目标提供端。已有AI预计援军调用也须复用同一候选逻辑，避免实际响应与预测不同。

官署法理更新会触发原版基督教局势地区缓存重算；本机原版住所扫描会把历史空缺教区住所的无效主人送入参与者校验。必要的单局势兼容覆盖只关闭六组共享的不安全住所扫描，以`tca_church_domicile_*`安全收集实际core内有效住所主人，再交原生manual入口与原参与组规则判断；不改资格、区域、阶段或历史住所。已有原生manual来源不接管，后来取得原生教职来源者保留登记。头衔、政体及自然旅行移动由二级回调排队次日同步；直接脚本迁移等无回调变动由原局势月维护补漏，不能声称与原生逐帧缓存等时。覆盖理由、基线及八个追加入口归上游登记维护。

收复按已确认的取舍支持1—128个精确县目标，保留原来的目标、计分与归还规则。原生重复`target_title`能逐项声明确定数量的县；实现按实际县数选择对应声明，不重复补位。128是当前实现的明确容量，不是引擎硬上限。超过128县整案不建立特殊收复战争，不截取前128县、不扩大成公国，也不拆成多场战争；防御响应与结算前快照不受这一容量限制。12县、128县及129县拒绝边界的实际证据与入口见[验证页](verification.md#通用争地战争响应与收复实施状态)。

没有采用自动配置替代：该入口只取第一组配置，已执行的12县对照实际只取得1个原生县目标。完整失地记录或战后归还集合不能冒充完整战争目标。128扩容采用明确声明，未改变这一原生接口限制。

首版只处理启用后新开的战争，不补建旧战争的承诺或失地。同战按战争变量去重；旧调试记录缺少`tca_ws_schema = 2`时关闭旧待援／收复并按保留期清理，不补猜旧归属。普通游戏的独立开关`tca_ws_automatic_response_allowed_trigger`启用白名单；CLI适配只关闭本模组自有开关，专用WORLD通过自备报告者接入，不处理背景战争。此开关不授予自定义有限战争宣战权限。

### 当前共享接口

`tca_ws_collect_goals_effect = { LIST = ... }`在战争作用域运行，输入`tca_fs_record`、`tca_fs_defender`及`tca_fs_attacker`，向记录指定列表写入去重县集合。开战响应用`tca_fs_goals`，结算前重新适配用`tca_ws_resolution_goals`；后者与原归属快照保存在`tca_ws_pre_losses`，不能拿开战归属代替战争期间合法转封后的归属。共同原版效果及其调用端、征服／扩张共享转属效果与资格均登记上游依赖。

响应行保留原生限时变量。继承事件只登记实际头衔承接者；完整继承落定后按原角色重新核验，合并同人响应但保留各原计时来源，任一原定到期点达到即可履约。结算前也解析已落定的继承，避免同日继承并议和时漏掉承诺。已参战状态由实际加入回调锁定，不能退出后重新成为未到达承诺。仅真实死亡会设置短暂的继承事务保护；相关战争、头衔与资格完成核验后即清除，不给改隶或失效失地续期。

国家以战前最高领主的主头衔作代表，继承后仍须是同一独立国家的主头衔；不沿原人物或继承人的外国更高头衔追入第三国。

实际失地逐县保存原主、原直属领主与政体，区分直接夺地、原主持县改隶，以及原主同时被本次战果转入敌国／敌国宫廷但县已换主的情况。特殊收复依据真实受益人选择敌方主体；不在原进攻者辖下的失地只能向已核实持有全部目标的原敌国最高领主追讨。每次接受、维护与胜利先剔除失效县，全部失效才停止。沿用原D事务边界：归还县及基层附属关系，不复建已销毁公国；原直属上级已无足够爵位时归原国家代表，详见[现有归还事务](design.md#追讨决定与衔接)。

实现文件分工如下：`tca_frontier_support_*`继续拥有共享候选、书信、计时与记录；`tca_war_response_effects.txt`及同名前缀trigger提供CB适配和官署辖区；`tca_war_response_resolution_effects.txt`提供原版结算前后快照；两个`succession_effects`文件分别拥有防御承诺与收复继承；`tca_frontier_recovery_*`拥有收复资格、宣战、归还与通知；其中`tca_frontier_recovery_targets_effects.txt`集中维护1—128县槽位清理、按完整县表填充及逐数量的原生精确声明，修改容量须三处同步。北疆局势及有限战争资格仍留在原消费者。

## 执行顺序与验收

当前实现的调用顺序为：开战回调按白名单及目标建立唯一记录、收集候选并投递书信；接受后保留原生到期点，继承与加入回调更新同一承诺；结算前共用效果重新适配县集合、保存合法归属并冻结未到达上级；胜方回调核对真实失地，再移交收复流程；原任务停止后按保留期清理。收复接受时再次清理失效目标，准备完整精确声明，在本次声明内临时豁免撕约罚；胜利时再核对归还范围。

维护时按实际受影响路径选择已有用例，保留白名单不同结算族、双战争隔离、真实继承与原到期点、改隶及额外土地、已参战者去重、停战与临时flag清理、128县完整目标与129县整案拒绝、保存重载的验证边界。不同CB可复用同一适配族用例，但不能以自定义CB通过冒充原版分支通过；书信、正式声明、真实战果和自然延迟也不能全部由直接worker调用替代。通过与未解决问题统一归[验证页](verification.md#通用争地战争响应与收复实施状态)维护，不在本页保留普通运行计数。

当前未接入的`influence_war_cb`与和约中央责任识别缺口见[原版召唤参战](ai.md#原版召唤参战)。后续是否适配另行确定，保留原版召唤互动，不把另建中央出兵系统列为共享层待办；最高领主直接开战继续遵循原版资格。和约独立规则见[和约页](treaties.md)。
