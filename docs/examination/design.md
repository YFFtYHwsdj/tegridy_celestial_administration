# 自动科举的设计取舍

当前行为和数值以[模块入口](README.md)及正式脚本为准。本页只维护为什么采用这些机制，不复制职位、费用和分数定义。

## 关键决策的状态

以下事件代办、头衔冷却和显式考生通知均为当前采用的实现取舍；待验收项目见[验证说明](verification.md)，不能把采用决定理解为已完成验收。未实现的舞弊、考官人情等属于当前范围边界，不是已排期任务。

重新评估事件代办的条件是开始要求旅行、邀请或考官关系参与结果；此时先检查原版活动是否能直接承载需求。重新评估活动整份覆盖的条件是原版提供独立扩展入口或上游对象发生变化，须结合覆盖清单审阅。若将来增加家主汇总，应同步重审逐人通知的去重与接收者规则。

## 事件链与原版活动并存

目标是让玩家皇帝可委任知贡举处理会试／殿试，同时保留亲自主持的原版活动。代办使用事件链结算，省去旅行、邀请、考官和活动场景；AI皇帝继续走原版活动。不能把代办称为完整复刻原版科举活动。

知贡举使用原生宫廷职位与任务，复用薪资和人物适配度显示。实际调度由皇帝承担：无地官员可能有独立的同僚隶属关系，不能假定职位员工的 `scope:liege` 就是中国皇帝。宫廷界面对无地官员的实际录用仍需验收，不另建任命副本。

## 考生、录取与规模

从王朝循环的原版参与者范围取候选，保留未过乡试分数折减、重考条件、原版功绩与及第状态。代办按普通规模抽样，符合召集条件的玩家近亲作为额外名额；先排除普通池中的优先近亲，再追加，预估与真实结算使用同一口径。

现任行政官员排除，避免以科举重复改变任官状态；宫廷职位与廷臣身份不一概排除。录取侧重受当前阶段限制，录取尺度由知贡举属性和原版权重决定，适配度不重复变成考试收益加成。

## 冷却、扣费与重入

自定义五年冷却保存在中国霸权头衔上，跨皇帝继承保留制度状态；同时维护原版会试计时，避免两条路径各自认为可开科。开始即认领 pending，年度检查、请开科及代办入口均校验；切回常规任务不取消已付费考试。

选项展示与实扣读取同一规模费用；内部随机和实际扣款隐藏，使用原生费用悬浮。亲自主持选中即关闭事件并打开原版活动窗口，避免活动后再回事件付款。零考生仍已发生主持成本，因此保留费用、收益及冷却，以独立结果事件结束。

## 通知与兼容

隐藏结算根作用域为皇帝，家族通知必须显式保存并引用实际考生。原版活动的家主汇总在代办中不存在，因此不能保留排除家主的过滤却不给替代通知。

原版会试活动缺少独立可追加的开办条件入口，采用整份活动覆盖，仅为玩家增加本模组冷却；完整原版基线登记于覆盖清单。游戏升级或其他科举模组改写同对象时，须重新审阅，不自动合并。

## 有意保留的范围

不加入舞弊、贿赂、考官人情和落第拜师；这些依赖原版活动上下文，若扩展应单独设计。当前没有用显示脚本推断通知送达、事件画面或保存重载已经通过，验收见[验证说明](verification.md)。
