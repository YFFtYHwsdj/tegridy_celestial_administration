# 提刑机构、任命与生命周期

查适用条件、绑定及启停，读[当前实现](#当前实现)；查补位和继任，读[原生任命](#原生任命与旧法兼容)；补历史人物前读[固定目录](#15-路与固定-id)及[研究接入](#后续补入历史人物)；调任估值见[任命重要性](#任命重要性)。真实交互和保存重载的判定另见[司法验证](verification.md)，本页不存逐轮结果。

## 当前实现

司法制度法律的全境维护在原生 `on_after_pass` 中执行，当日撤任及退出真实路法理树；启用时当日任命并挂回。`on_pass` 仅设置冷却，次日复核继续保留。修复前后复现及验收边界见[法律回调时序](verification.md)。

### 适用范围

持有者为天朝政府且司法制度启用的有地王国级路：包括最高王国级的非独立文官主官，以及帝国／天下级独立皇帝持有的路。军事与都护契约仍排除。路须有持有人及可用首府；未创建或无持有人的路不设职。

同一符合条件的持有者如果拥有多个路，按各路头衔分别绑定。有效在任时提刑司法理上级为绑定路；停用、废置或销毁时退出真实路法理树，恢复后挂回原路。地方主官持路时实际隶属该主官，皇帝持路时实际隶属该皇帝当前可用且等级高于公国的刑部大臣，无可用刑部时暂隶属皇帝。换任、失去职位、被关押和获释通过原生回调维护；囚禁与释放先同步已有官署隶属，再请求次日完整维护。刑部取得职位也请求维护，覆盖保留刑部头衔的重新任职。原版囚禁会导致内阁空缺，释放不自动恢复职位；真正重新任职后恢复直属刑部。该法理与刑部挂靠整合未提供完整旧存档迁移；既有旧法及固定绑定兼容见下文。

### 头衔对象

- 公国级无地头衔，不在地图上划县。1066 开局的指定 15 路使用 `d_tca_judicial_*` 固定定义；其他开局与未列入的辖区继续动态创建。
- 头衔命名为“某路名＋提点刑狱司”，继承路的纹章。
- 持有者称为“提点刑狱公事”，不附加路名；机构名仍带路名，与官员职名分开。
- 先设置引擎要求的首选首府县，再设置无地属性。优先引用路头衔首府，缺少时引用观察使的首府；两者都不存在则暂不创建。
- 首府字段仅用于引擎定位，不授予县，不创建官署建筑，也不赋予该县的收入或军队。
- 禁止自动宣称、王朝命名和游牧命名。
- 动态与固定官职均保留对象和所属路绑定。撤销时以 `destroy_title` 撤销当前持有状态，并退出真实路法理树；提刑司本身始终关闭 `delete_on_destroy`，恢复时复用原 ID。不设置继承即销毁。
- 持有者称号通过 `flavorization` 与 `TCAJudicialHolderTitle` 自定义本地化接入。仅检查主要头衔的本 mod 标记与路绑定；非提刑的普通天朝公国持有者回退原版节度使称号。配偶不获得提刑称号。
- 该桥接条目优先级为 28，高于原版普通公国称号的 27；其他 mod 的更高优先级条目可能覆盖，需要组合测试。
- 机构名仅为头衔显示名称，不创建官署建筑或部门系统。

固定头衔的历史文件暂未填写任职者；`holder = 0` 是待考数据占位，不是史实空缺断言。退出大厅后的维护仍按既有流程选任合格的非历史人物，无人可选时生成文官，建立家族、政府及直属路关系。因此目前没有可在大厅直接选择的历史提刑人物。未来补入历史任职者后，仍需验证其开局政府、专职资格和封臣关系。

### 绑定

路上保存 `song_judicial_title`，官职保存 `song_judicial_circuit`，后者带有 `tca_judicial_title` 类型标记。有效性检查要求双向一致。

使用 `tca_judicial_circuits` 全局列表记录本 mod 管理的路，以便清理已失去持有者或已转出适用制度的对象。普通维护只操作本 mod 绑定，不销毁其他 mod 的头衔。

### 生命周期

- 1066 固定机构的头衔历史声明所属路并建立引用；退出大厅后的维护先执行每存档一次的补接入口，再扫描相关领主。已有有效绑定直接复用，没有绑定时直接读取路上的固定对象备用引用，再回退动态创建。无人头衔历史效果是否在大厅执行仍待验证。
- 获得王国头衔或改变政府后，通过隐藏事件延迟一天检查，避免在变更中间状态处理。
- 路销毁：交接公职囚犯并撤销提刑任职，移出真实路法理树，保留官职对象、双向引用及登记。路恢复适用后复用原官职。
- 提刑官职被外部销毁：交接公职囚犯，移出真实路法理树并保留路绑定；路仍适用且未废置时，后续维护在同一对象上补位并恢复法理。外部模组主动删除对象不在本模组保证范围内。
- 每年对已登记路做失效清理，并扫描符合条件的路补建。
- 普通观察使换任：新持有者检查到已有双向绑定，复用原官职。
- 转出文官路或由不适用的持有人持有：按当前适用范围撤销官职；独立皇帝持路仍在适用范围内。

创建前验证绑定，重复运行不得生成第二个官职。销毁回调交接囚犯、维护持久标记并处理法理脱离，不递归销毁提刑司自身。空缺对象不重复执行持有状态的销毁事务。原生空上级写法未获支持，当前内部通过退役临时父引用脱离真实路；不宣称该字段为空值，法理回归与保存重载边界见[司法验证](verification.md)。

显式废置设置 `tca_judicial_disabled`，季度、年度与延迟官职维护均不补位；显式恢复清除此标记，在原对象上任命。路暂时失效不设置此标记，恢复适用时在原对象上补位。绑定存在不等于官职正在运行，任命与权限还检查制度、废置标记及持有者。

维护时恢复机构身份。15个已登记路使用稳定机构本地化键，显示时通过GetTitleByKey读取路名，因此改名不依赖临时scope；同一路的旧动态机构也复用这一键。其他自定义路继续使用set_title_name_dynamic，随维护更新名称，原生自定义文本可能仍产生缺键提示。

## 开发入口

角色作用域：`tca_refresh_character_circuits_effect = yes`，检查角色当前持有的路。

路头衔作用域：`tca_ensure_judicial_title_effect = yes`、`tca_restore_judicial_title_effect = yes`。

路头衔作用域的销毁和废置效果要求预先保存角色 `scope:tca_lifecycle_actor`；它是执行 `destroy_title` 的作用域，不获得官职。

在当前玩家为观察使的调试控制台中，可分别检查：

```paradox
effect tca_refresh_character_circuits_effect = yes
effect save_scope_as = tca_lifecycle_actor primary_title = { tca_abolish_judicial_title_effect = yes }
effect primary_title = { tca_restore_judicial_title_effect = yes }
```

这些命令仅供开发验证，不添加面向普通玩家的测试决议。关闭或卸载 mod 并不会自动执行脚本清理；本阶段不要把测试存档当作长期存档。

## 原生任命与旧法兼容

官职不再安装专属继承法，直接沿用持有者的原版 `celestial_appointment_succession_law`，由该法调用原版 `celestial_civic_governor`。
不再克隆任命类型：评分、功绩门槛、`allowed_candidate_tier = lower_or_equal`、`cooldown = yes` 全部沿用原版。
允许地方文官公国与提刑同级调任，但仍要求新职位重要性更高，并遵守近期任命等资格限制。
原版近期任命期限为 1825 天（五年）；不能承诺每个同级官员都能立即接任。
文官池分类还涉及原版文武特质/契约；相同任命类型不代表每个头衔显示完全相同的最终顺位。
提刑已接入专用重要性：基础分 250＋所属路法理县月收入合计×8＋原版距京项；其他头衔保留原版算法。详见[任命重要性](#任命重要性)。双向升迁仍须检验新职位重要性更高及其他任命资格。
补位仅用于空缺或交接后不合格状态，不因 current_heir 为空而撤换合格现任。
候选池仍受原版性别、契约、功绩等规则约束，原版继承法不保证永远有普通候选人。

继承/获得其他头衔/政府或领主变更后延迟一天校验。
合格者必须无地、天朝、公爵级、以本官职为主头衔，且其他持有头衔只允许家族头衔。
空缺或不合格在任者走原有补位算法；补位候选除家族头衔外不能持有其他头衔，避免低级无地官职兼任。脚本只请求转移提刑官职，原持有者的领地和家族是否保持须按下面步骤验收。
首次与纠错任命保持历史角色排除；原版自然继承到合格历史人物时不撤换。
重新归附和政府/家族初始化结束后确保原版领地法，移除旧版提刑专属法，统一恢复名称、纹章及两个销毁标记。
季度角色脉冲及年度全局维护兜底；不增加每日全世界扫描。

### 旧法兼容

旧存档先记录原官职、持有人、领地法和双向绑定，再于可丢弃副本触发正式维护；不在正常游玩档运行测试决议。
维护会确保合格提刑持有者具有原版文官领地法，并移除绑定官职上的旧版专属法；对观察使兼持等不合格状态另选或生成无地官员。加载存档时的开局维护也可能已完成迁移，所以查看基线时旧法不一定仍存在。
旧法定义仅为存档兼容保留：禁止新添加，维护只移除本 mod 的旧法，不清空其他头衔法律。
旧法兼容不直接编辑存档，不改全局冷却、原版任命类型、路领主或皇帝的继承法。
现有两个销毁标记修复和显式废置逻辑继续保留。

### 任职稳定性

资格校验比较本官职与 `prev.primary_title`，不能把无效作用域当成不合格而每日轮换。维护有效现任时保持持有人；让其取得实地或另一非家族头衔后，只对原官职补位，不转走新领地。连续推进及保存重载的验证见[司法验收](verification.md)。

## 实现入口与旧存档

- `common/landed_titles/tca_judicial_titles.txt`：15 个独立顶层定义，不嵌入原版路的法理层级。
- `history/titles/tca_judicial_titles.txt`：每个机构在 1066.9.15 的 `effect` 中以 `CIRCUIT = title:k_*` 声明对应关系；人物留空，不覆盖原版头衔历史。
- `common/scripted_effects/tca_judicial_static_title_effects.txt`：通用绑定器在官职作用域接受 `CIRCUIT` 参数，设置路上的 `tca_static_judicial_title` 备用引用，并在没有有效现职绑定时建立双向引用和登记。既有动态绑定不被覆盖。标记 `tca_judicial_static_title` 只表示固定对象来源。
- `common/scripted_effects/tca_judicial_title_effects.txt`：有效双向绑定优先；无绑定时清除临时官职作用域，先查固定对象，再动态创建。固定对象通过路上的备用引用直接读取，不再按路 ID 执行 `if / else_if` 查找；两者随后共用任命和身份维护。
- `localization/{simp_chinese,english}/tca_judicial_static_titles_l_*.yml`：无人且尚未初始化时也有静态机构名及形容词；运行中使用稳定的机构本地化键，通过GetTitleByKey读取所属路当前名称；旧动态机构属于这15路时也使用同一键。

旧存档已有有效动态绑定时保留对象、现任官员及囚犯记录，不自动迁移到固定对象。旧存档不会重新执行头衔历史；全局维护先执行一次有界补接清单，每个固定机构一行，调用与历史相同的通用绑定器。它也兜底处理无人头衔未执行历史效果的情况。无有效绑定时才接入固定对象；新定义能否在旧存档加载时被完整纳入仍待验证。其他路仍动态创建。补接清单仅在 1066 开局执行，并由 `tca_static_judicial_bindings_v1` 标记限制为每存档一次。修改或新增历史映射时须同步该清单。

废置时先交接公职囚犯，再销毁当前持有状态；动态与固定官职均保持 `delete_on_destroy = no`，不解除双向绑定或移出登记列表。显式废置保留 `tca_judicial_disabled`，季度、年度与延迟维护均不补位；恢复复用原 ID。暂时转出适用制度的路也保留官职，恢复文官路时复用。

固定机构目录本身为独立定义；本模块任命重要性、命名及刑部任职回调另有原版覆盖，不能由固定目录无覆盖推定整个模块无兼容影响。

## 后续补入历史人物

历史依据统一见[1066开局提刑考证](../../research/song/1066_tidian_xingyu/README.md)，写法与分级见[考证规范](../../research/standards.md)。当前研究覆盖18个游戏路，包括本固定目录以外的三军路；研究范围不等于当前机构适用范围。人物判断、游戏适配、是否写入历史及引擎验收分别记录，固定机构仍未填写考证人物。

在 `history/characters/` 增加或引用经过考证的角色，在对应固定头衔的日期块中填写 `holder`、天朝 `government` 和所属路 `liege`，保留通用绑定效果。有更早任期时需移除或调整现有 1066.9.15 的 `holder = 0`，避免覆盖有效任职。不能只增加人物而不授予官职。

记录史料依据、日期可信度与原版人物 ID 是否复用。历史人物的政府、家族、功绩及任命继承仍应检查；现有补位算法保留合格在任历史人物，但不会把其他历史人物随机抓来填空。史料明确的空缺与尚未考证的任职者应分别记录。

## 任命重要性

### 公式

提刑重要性反映路级司法官职的吸引力，用于原版同级调任比较，不替代功绩等级、候选评分或近期任命冷却。

初始公式：

```text
提刑重要性 = 250 + 8 × 所属路法理县月收入合计
                 + max(0, 500 − 0.0001 × 路所在地与最高领主首都的距离平方)
```

经济项为原版文官经济权重 24 的三分之一（权重 8）。路是王国级辖区，通常包含多个公国；按三分之一折算，再加固定官职分，允许部分提刑职位高于部分地方公国，同时保持不同地区的差异。基础分 250 与经济权重 8 是当前平衡选择，尚未依据游戏内职位分布校准；不保证所有提刑都高于或低于地方公国。

收入采用绑定路的 `every_de_jure_county` 和 `title_province.monthly_income`，不是提刑自身收入、俸禄、办公预算、国库税收或实际司法案件数量。法理辖区可能与实际控制的司法范围不同；本版沿用原版法理经济口径，包括路的法理范围中不在本国实际控制下的县。距离使用引擎内部单位，不是公里。

例如，路的法理县月收入合计为 80，距京项为 400，则提刑为 1290。一个月收入合计为 20、距京项同为 400 的地方文官公国为 880；另一个收入合计为 40 的同位置公国为 1360。仅从重要性看，前者可调任提刑，提刑可调任后者；实际资格仍由原版任命系统决定。

### 实现与作用域

- `common/script_values/appointment/tca_judicial_appointment_values.txt`：`tca_` 前缀的基础分、经济权重及完整提刑公式。ROOT 始终为被评估的提刑头衔；收入与距离切换到 `var:song_judicial_circuit`。
- `common/script_values/appointment/zz_tca_appointment_values.txt`：对象级覆盖原版 `appointment_title_value`。有 `tca_judicial_title` 标记的头衔直接执行提刑公式，不依赖持有者的原版文官契约标记；通判标记另走[通判公式](../tongpan/README.md#任命重要度)，其余头衔执行完整保留的原版算法。
- `localization/english/tca_judicial_prominence_l_english.yml` 与简体中文对应文件：重要性分解中的官职基础分和辖区经济项；距离项复用原版文本。

缺失路绑定时只有基础分；有绑定但无持有者或缺少定位时，只计算基础分与辖区经济项，不读取不存在的距离目标。正常生命周期仍应修复绑定和持有者；这些保护不是头衔状态有效的证明。

计算在读取脚本值时执行，不把分数写入存档。经济变化和最高领主首都变化会影响后续计算；候选池及界面何时刷新仍由引擎决定。重要性取值不增加维护扫描，不改变任命资格、冷却及补位流程。

### 原版依据与兼容

参考本机 CK3 1.20.0.4：

- `game/common/script_values/tgp_values.txt` 的 `appointment_title_value`：文官收入权重 24、距离项、武官与中央大臣公式。
- `game/common/script_values/10_ach_values.txt` 的 `oath_reconquest_value_1`：脚本值内切换变量头衔作用域并遍历法理县的原版写法。
- `game/gui/window_title.gui`：头衔页通过 `GetScriptValueBreakdown('appointment_title_value')` 显示分解。
- `game/common/succession_appointment/celestial_governor.txt`：文官允许同级候选，启用近期任命冷却。

引擎与 GUI 使用固定的原版脚本值名，因此仅新增 `tca_` 值不能接入，需覆盖该原版对象。未覆盖整份 `tgp_values.txt`；非提刑分支保留原版函数体和 ROOT 语义。与其他覆盖同一对象的 mod 存在冲突，不能自动合并。游戏更新后需复核保留的原版分支，该对象已纳入[原版覆盖检查](../development/upstream.md)，具体登记以清单为准。

## 维护顺序与命名适配

取得头衔、政府及领主变化统一通过 `tca_request_judicial_maintenance_effect` 合并次日维护；排队标记在 worker 执行期间保留，结束解除，防止自身授职回调再次排队。囚禁／释放先同步已有官署隶属，再请求完整维护。

已登记路使用稳定本地化键及 `GetTitleByKey` 读取当前路名；其他辖区保留动态文本命名。头衔升阶接入的原版命名 trigger 只将头衔路径的 `capital_county` 修正为 `title_capital_county`，完整原版基线与兼容范围见覆盖清单。旧存档已有动态官署不会为统一 ID 而迁移。

旧法兼容只移除本模组废弃继承法，不能理解为完整旧存档迁移保证。双向调任、多个连续死亡、真实界面名称和保存重载的验收见[验证说明](verification.md)。
