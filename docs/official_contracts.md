# 无地官员契约

## 当前实现（2026-10-18）

适用于以标记提刑或通判官职为主头衔的无地天朝臣属，世族头衔不纳入。身份项直接显示“提刑”或“通判”，移除预留武官项及通用文武分类。通判基础每月功绩+10，提刑+20，均关闭头衔兵士。

身份树 `tca_official_obligations` 保留“无”及两个按主头衔互斥显示的官职项：`tca_official_judicial` 为提刑，`tca_official_tongpan` 为通判。直接使用原生 `monthly_merit`，维护按具体官职核对档位和独立身份标记。功绩不与经费契约档位挂钩，当前不引入浮动功绩；人物原生功绩倍率仍可改变最终收入。`appointment_trait_flag = civilian_province` 仅保留原版任命特质分类，不再作为界面身份名称。

个人俸禄完整沿用原版 `celestial_salary` 五档及隐藏的 `celestial_salary_rank`。原版仅向主头衔至少公爵级的人物显示俸禄契约；伯爵级通判不显示该调整入口，按用户确认保持原版，不新增显示覆盖。入口隐藏不能据此推断没有俸禄收入。办公经费拆为互斥显示的路司经费 `tca_circuit_office_budget` 与通判经费 `tca_tongpan_budget`，共用地方国库结算，不再借用中央朝臣预算：路司五档2%／4%／6%／8%／10%，通判5%／10%／15%／20%／25%，默认第三档。基数、付款关系、月结与GUI边界见[地方官署经费](office_funding.md)。拨款五档对契约领主好感为-25／-15／0／+5／+10，与原版五档 `celestial_salary` 一致；原版三档朝臣预算为-15／0／0，不能将其高档误记为正好感。好感对象仍为原生契约领主，不改成辖区付款人；五档契约协商分值为-2／-1／0／1／2，AI改变意愿沿用零值。

预算待遇随头衔保存，任免不重置。领主发起与官员请求获准两条原版行政改约路径都调用 `tca_record_changed_office_budget_effect`，只在实际变动的项目是本署经费时记录预算；维护恢复已有档位，不改其他俸禄或权限。当前官员主头衔入口尚不提供对任意兼任官署逐一改约的界面。

## 改约权限（2026-10-19）

当前经费改由独立管理／请求互动承载，横向五档、每次只能升降一档、两位管理者各自5年冷却。原契约页的经费保留只读显示，个人俸禄仍走原版。原契约页底部新增经费调整按钮，可转入完整双栏窗口；非直属州长官使用同名人物互动。当前实现、AI与验证边界见[官署经费调整互动](office_budget_interactions.md)。独立入口完整回归120用例／749断言通过，经费用例62断言覆盖真实发送；下文原生窗口实验仅保留为实现依据，当前界面像素验收边界见该文档。

通判：对应州长官及该州长官的直属领主有权修改；不自动向更高层级开放。提刑及其他原版行政臣属仍由实际直属领主修改。权限入口 `tca_can_edit_admin_contract_trigger` 位于官员人物作用域，参数 `EDITOR` 为修改者；通判分支同时核对有效专职持有人、州资格、同一政权及州与通判司的双向绑定。官职身份项仍由维护锁定，不能手动把通判改成提刑。

管理者资格不改变实际领属、国库付款人或好感对象。通判仍由对应州国库付款，原生 `subject_opinion` 仍作用于其契约直属领主。两位管理者分别使用官署头衔上的地方／上级冷却，均为5年，互不消耗机会；不写入个人俸禄改约冷却。官员自己的经费请求使用独立互动，仍面向实际直属领主，接受方也必须符合上述权限。

`admin_liege_modify_vassal_contract_interaction` 调用统一授权入口并保留窗口要求的实际直属关系；`admin_vassal_modify_vassal_contract_interaction` 保留原版直属请求条件，追加同一授权检查，并在接受时接入头衔待遇保存。两条路径共用保存入口，避免官员请求成功后被维护恢复旧档位。原版费用、拒绝／强制接受、牵制、家族和冷却逻辑保留；工具对请求侧覆盖与完整原版基线进行逐token对照，只允许新增授权和保存。

覆盖范围包括 `celestial_vassal` 契约组、`celestial_treasury` 显示条件及两侧行政改约互动；没有整份替换政体或契约文件。新增请求侧覆盖登记于 `tools/upstream_overrides.json`，完整原版对象单独保存为已审阅基线。与改写同对象的其他模组可能冲突。只面向新开局，不迁移旧三档存档。

### 本轮验证与原生窗口限制

环境为 CK3 1.20.1.1 macOS ARM64、独立1066新局、种子1538798675，仅冻结主模组与测试适配。正式 `tca_office_funding_test.1` 单项 `run-ocbypg8a` 的43断言全部通过，包括州长官、其直属领主、提刑直属上级的授权与自身、无关人物、错绑反例。该次检查43使用既有其他官员作为无关人物；随后加强夹具，改为新建无头衔的无关人物，不改变权限实现。当前夹具在 `/private/tmp/tca-contract-rights-final/run-xe08g079` 复测为1用例、43 CHECK_PASS，零失败或未执行；观察者、summary、源码快照及同次日志核对通过，runner与verification退出码均为0。该组没有发送真实改约互动，不证明窗口及完整结果。136项工具测试、上游覆盖与范围内格式检查通过；本轮未跑全组。

用户提醒后另用 `run_interaction` 实际发送原生 `admin_liege_modify_vassal_contract_interaction`。本机生成的 `effects.log` 说明该effect接受角色、重定向和响应阈值，不提供契约选档参数。实验将 `vassal_contract:tca_tongpan_budget.obligation:tca_tongpan_budget_increased` 加入调用事件的 `changed_obligations` 后，使用 `redirect = no`、`send_threshold = decline` 发送，未使用强制执行或直接调用接受效果。`/private/tmp/tca-contract-run-interaction/run-9s670exp` 为43通过、5失败、NOT VERIFIED；州长官、州长官的领主及提刑实际直属上级均被“必须提出契约变更”阻止，调用事件中的列表没有成为互动自身的选档数据。由此只能否定该输入方法，不能判定这些人的实际权限。原始48断言实验源码及日志保留在该次冻结快照，标准事件恢复43项有效断言；不得把输入方法失败说成业务测试通过。

实际窗口探针位于 `/private/tmp/run_tca_contract_rights_probe.py`：准备有效绑定，切换真实玩家至管理者，再调用 `open_interaction_window`（`redirect = no`），由窗口实际选档和发送回调处理；不直接调用正式 `on_accept`。`/private/tmp/tca-contract-rights-window/run-7jqqdj9m` 中州长官失败，直属上级成功，整轮 NOT VERIFIED。`debug.log` 明确报错于 `modify_subject_contract_interaction_window.cpp:297`：`They are neither direct vassal/liege nor direct tributary/suzerain of each other.` 此项错误写在debug日志中，不能因error日志筛选未命中而认为没有窗口错误。

实际直属上级成功改为第五档，头衔保存为4，调用正式维护后仍为4。州长官没有生成可选档窗口，档位与保存值保持原值，故不是发送后被维护回滚。当前已证实此原生窗口要求双方存在直属关系；仅放宽脚本 `is_shown` 无法完成州长官改约。该实验说明必须另选操作入口；当前替代交互见上文及独立经费互动文档，官职实际领属不变。
