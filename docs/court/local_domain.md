# 州郡兼领法

本页是州郡兼领法规则、实现与验收的主要维护位置。该国家政策只改变地方官员的直辖容量，与中央／地方官名、司法及通判制度分别选择；公国持有和自动转授土地不在本制度范围内，任命评分、行政契约及头衔继承规则也不随之修改。

## 规则与范围

- **量才兼领**：不额外限制地方文官与军事长官的直辖上限。
- **文臣专领**：地方文官最大直辖容量为1，军事长官不受此项限制。
- **文武专领**：地方文官与军事长官最大直辖容量均为1。

只有独立天朝统治者可以颁布，对实际领主链中的各级天朝地方官员生效，不按法理辖区判断。

- 最高统治者豁免；帝国级地方长官不因头衔等级豁免。
- 文武身份分别读取原生契约的`celestial_civil_appointment`和`celestial_military_appointment`，不按称号、教育、是否带兵或内阁身份推断。中央官员若兼领地方行政领地，也按实际地方契约判断。
- 无地官署、仅持家族头衔者、非天朝封臣及未能识别文武契约者不受限制。家族庄园不另计。

限制使用原生`domain_limit_max = 1`，不改变原生直辖计数方式，不新增下限，也不以大额负数抵消其他容量加成。现任超限沿用原生后果，不由同步脚本强制收地。量才兼领只移除本制度限制，不移除其他模组已有的限制；涉及其他最大／最小容量修正时须实际核验叠加。

每次改革花费2000威望和1000影响力，改革者不得被关押，三档可以直接互换，独立冷却十年，不与司法或通判改革共用。第一版AI不主动切换政策，但遵守现行政策及继承结果。

## 原生法律与同步

国家三档政策没有直接容量修正；独立后台法律组包含正常容量和上限1两法，不提供玩家自行改革入口。采用原生后台法律，是为了让日常有效性检查接管身份变化，避免覆盖天朝政体／行政契约或另行维护定时角色修正。

同步分为两条路径：

1. **颁布政策**：`on_pass`只设改革冷却；`on_after_pass`读取替换后的政策，为本人和各级真实臣属设置正确后台法。角色同步幂等，后台法通过跳过颁布效果的原生入口安装，不重复收费、不续冷却、不修改契约或头衔。
2. **日常变化**：后台两法的`can_keep`和`should_start_with`读取同一个正式判断，由原生检查处理文武契约、领主及任职变化，不增加年度、季度或身份变化回调。

**生效时机**：颁布回调在同次执行中换好后台法，但引擎可能继续读取该脚本链缓存的旧`domain_limit`；容量数值另在次日回归核对，不为刷新读数增加玩法回调。日常变化按原生检查周期更新，本机原版`common/laws/_laws.info`说明失效法律在一个月内替换；周期回归每阶段真实等待35日（跨一次原生月界即可），不以同步effect替代自然检查。

## 初始化与保存

原生政策默认量才兼领。仅在既有`on_game_start_after_lobby`回调追加新局初始化：1066.9.15及1178.10.1开局的`h_china`持有者采用文武专领，其他独立天朝统治者保留量才兼领，并立即同步。这个宋代默认值是本模组的游戏采用，不表示史实中存在对应的量化直辖制度。

初始化标记随人物保存，重复调用不重置已有选择，也不按年份或官名法律持续恢复宋制。原版默认初始化及法律继承不执行颁布回调，所以新局显式调用同步effect；继承后的后台状态仍交给原生检查。

代码对缺失该政策的旧档使用原生默认量才兼领，不按旧档的开局日期补颁宋制；已有政策应保留。真实旧档接入尚待独立验收，不能以新局重复初始化或本版本保存重载代替。

## 验收与边界

### 自动回归

用例由[`local_domain`模块](../../common/scripted_effects/tests/modules/tca_test_modules_local_domain_effects.txt)登记，实际断言以当次冻结计划为准：

- [`tca_local_domain_test.3`](../../events/tests/tca_local_domain_test_events.txt)：1066开局默认及重复初始化不覆盖选择。
- 同文件的`tca_local_domain_test.1`：正式`add_realm_law`颁布后同链后台法律、次日容量、重复同步、间接封臣、独立冷却及头衔保持。
- [`tca_local_domain_native_test.1`](../../events/tests/tca_local_domain_native_test_events.txt)：三档政策、文武契约变化及独立后解除限制，真实等待原生检查，不手动补刷。
- [`tca_merit_saveload_probe_test.1`](../../events/tests/tca_merit_saveload_probe_test_events.txt)：与功绩共用唯一CLI检查点，另建人物验证国家政策、改革冷却和后台法律随存档恢复。保存后现场改回量才兼领并清除冷却，续局依赖原排队事件检查，不重新初始化或同步来修复结果。

各项通过[独立夹具](../../common/scripted_effects/tests/fixtures/tca_local_domain_test_effects.txt)新建官员，文官与武官分别借用帝直属州制、军制原路，清理时恢复原政策、持有人、行政类型和实际领属。军制夹具复用已占用的同类名额，文武契约互换先释放后取得，避免满额世界中把准备失败误作领地法恢复失败。主动换约时同时设置夹具路的临时行政类型，避免官署维护按旧军制类型补约；不调用领地法同步，仍等待原生法律检查。交还头衔前恢复原行政类型记录，含原先缺少记录的情况。独立场景只归还头衔不足以恢复帝直属关系，必须另做真实归附事务，并保留恢复断言，防止污染后续司法用例。

```sh
python3 tools/run_game_tests.py --suite local_domain --suite court --case tca_merit_saveload_probe_test.1 --timeout 600
python3 tools/run_game_tests.py --timeout 1200
```

运行隔离、两阶段观察者确认、冻结计划及日志核对遵循[统一运行契约](../testing/README.md#运行隔离与结果)。普通通过计数与运行产物留在仓库外，不在本页追加逐轮记录。

### 待人工或独立场景验收

- **政策界面**：在专用玩家测试局准备足够资源，经真实界面依次切换三档，核对费用、冷却日期、三档文案及次日容量；检查简中／英文与实际界面缩放。脚本颁布不证明这些界面路径通过。
- **其他开局与旧档**：分别新开1178中国和非宋代开局，核对各自默认；在旧档可丢弃副本中加入本版本，核对缺法时的默认及已有选择不被重置。
- **自然生命周期**：准备受限地方官员，经过自然授职、失职、君主继承、政体变化及跨政权归附，核对后台法在原生周期内更新；直接设置契约或脚本独立不覆盖全部原始触发路径。
- **长期与组合**：观察AI对实际超限土地的处理，并在涉及其他容量修正的模组组合中检查叠加；本模组的同步脚本不负责分地或取消外部限制。
