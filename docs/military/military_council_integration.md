# 地方军事内阁与军事差遣联动

## 实现状态与文档分工

官署判定与动态称号、差遣兼任与保护、玩家临时补位及任务交接已接入。原生用例覆盖与剩余人工项目见[回归与验收](#回归与验收)；共用流转改动的实际复测范围见[宫廷差遣验证](../court_positions/verification.md)。真实玩家界面、自然 AI、完整自然跨署迁转、旧存档与保存重载仍待验收，定向结果只支持实际执行范围。

本页维护军事选席映射、军事任务交接及相应验收边界；共用任免与生命周期由[统一差遣设计](../court_positions/design.md#内阁兼任与生命周期)维护，军事官署准入与专项任务见[军事差遣设计](court_positions_design.md)；[模块入口](README.md)提供导航，不再复制完整规则。

## 目标与边界

让朝廷派驻的兵马监押、兵马都监、都虞候通过原生 `councillor_marshal` 执行地方军事内阁任务。复用原生界面、任务和正常任免规则，不覆盖军事内阁定义、不增加世界扫描或另一套选官调度。

联动适用于天朝有地、非独立地方主官，包括帝国级地方封臣；独立皇帝与无地人物不进入地方联动。枢密使的都虞候准入不自动赋予地方内阁联动资格，仍须满足有地地方主官判据。三差遣能否设置仍以各自官署准入为准，不因联动扩大。统一判据为 `tca_is_landed_celestial_governor_trigger`。

采用兼任原生内阁的方案，是为了让已有军事差遣参与地方治理，同时保留原生任务。单纯改名无法落实任职者与权限；另建内阁对象会引入更多覆盖、界面和任务维护。历史制度表达属于设计目标；史料核验仍遵守[考证规范](../../research/standards.md)，不由联动脚本或测试代替。

## 持续资格与权限

- 待阙候选仍走原版全职排他，不从其他内阁、税吏或全职杂职中抽人。
- 任职期间，其他全职宫廷岗位及税吏继续排他。内阁身份只允许本署差遣兼任本主君的军事内阁，不豁免其他内阁职位。
- 地方差遣候选与任职者还须符合原生 `can_be_marshal_trigger`，包括性别、健康、囚禁和人质等条件。原有入品、知兵、本署廷臣及非领主条件不变。
- 有其他主君的 `block_fire_councillor` 保护时，不借军事差遣覆盖它。

`common/scripted_triggers/tca_military_full_time_job_triggers.txt` 保留原版全职岗位名单，仅移除其中的内阁身份总排除；正式资格另行精确检查合法兼任。原版对象以 `script_dependencies` 登记于 `tools/upstream_overrides.json`，更新后须人工审阅名单差异；该独立 ID 不属于同名覆盖。

## 就任与离任

三差遣共用就任、撤职、失效与出缺回调，任免及离任主体已抽入文武共用`common/scripted_effects/tca_court_council_effects.txt`，军事入口保留委派，使用原生提供的 `scope:liege`（官署主君）和 `scope:employee`（任职武官）。临时选席、离任者排除与任务交接的调用约定分别维护在对应正式效果旁。

同一官署可同时设置三种差遣，但军事内阁只有一个席位。统一按都虞候、兵马都监、兵马监押的顺序选择兼任者；低职晚到不替换高职，高职离任后由仍合格的低职接任。只有实际兼任者获得模块锁，其他差遣仍保留自身职位和任务。

就任及离任都通过同一选席入口；已在该席位时不重复任命。只有确认兼任成功、且人物没有既有原生保护变量时，才设置 `block_fire_councillor` 与模块归属变量 `tca_military_council_lock_owner`。

原版请愿等机制已有的保护不改写、不认领。离任时只释放模块归属与原生锁均指向该主君的保护；其他机制改变过的值保留。受到外部保护而无法正常解职时，不强行移除保护，也不反复执行被禁止的解雇。铨选只有确实需要换席时才检查这项限制；受保护高职在任不阻断低职补缺。候选还须通过目标宫廷的原生军事内阁条件，过滤耗尽时不沿用上一官署的选中人物。模块永久保护的中英提示说明“差遣在任期间不可撤换”，不显示虚假的今日到期；原版有期限保护保留原文。

撤职、失效、出缺共用一个幂等清理入口。原版 `_court_positions.info` 明确自然离廷和死亡属于 `on_court_position_vacated`，失效后也会出缺，而撤职不触发出缺；因此三种离任回调都接入，重复回调不会重复替换已有司马。死亡人物不再读写变量。独立回归曾在改制后的两日观察窗口内发现失效差遣仍被保留，因此政府变更子回调显式验证改制者自己的三种职位，并走正式撤职清理；这不是对原生所有失效检查周期的推断。

主君死亡测试观察到差遣可能撤销，也可能随宫廷保留；原生不保证清除员工身上指向旧主君的锁。死亡前只释放本模块自有锁，并向原来实际任职的武官排一个次日重绑事件。事件读取原生结算后的真实宫廷职位雇主，验证官署和人物资格后同步军事内阁；不预设王国、治所和家门由同一人继任。

## 玩家空缺补位

仅对玩家地方官启用。原生回归以模块专属 flag 启用此脚本分支；该标记不会将 AI 变为真人，也不证明玩家界面操作通过。必须同时没有正式军事差遣、没有军事内阁任职者，才从符合原版军事内阁资格且不在其他内阁任职的廷臣中按军事能力选人。

- 排除本次离任者，避免撤职后返聘及跨宫廷调任中短暂重新入阁。
- 不赋予模块防撤职锁，玩家沿原生规则任免。
- 已有司马时不替换；无人可选时保持空缺，不生成官员、不降低正式差遣品级。
- AI继续沿原生内阁补缺机制，不增加全图补位处理。

因此保证的是“有合格候选时自动补位”，不是永不断档。正式差遣到任仍可接替临时司马。

## 称谓与任务

只替换地方军事内阁的中英本地化键，经独立 custom localization 根据差遣身份输出称谓；没有差遣时回退默认称号。中英覆盖均登记原版基线。动态根作用域、空缺显示和实际界面仍须玩家验收。

引擎探针确认直接换人可以保留原生任务；显式解职再补位的路径需要交接保护。正式系统换席前保存玩家当前任务；新任命成功后，只有原生任务仍合法且未在执行同一差事/目标时才恢复，避免重启已保留的进度。

按已核对的原版任务 ID 映射组织军队、训练指挥官、管理禁卫和提升控制力四种地方军事任务；一般任务与县级任务分别恢复，不保存未经确认的动态任务类型对象。一般任务保存任务flag；提升控制力额外保存原生 `councillor_task_target` 省份引用。恢复使用原生 `is_council_task_valid` 判断，不复制任务合法性规则；失效县级目标退回默认差事，消费后清理快照。

无人补位时暂存任务与目标，待系统下一次任命。若玩家在此期间自行任命司马并改变差事，正式差遣到任前重新采集当前任务，新选择优先。自然迁廷及死亡分别以非默认任务和县级目标检查连续性；原生能保留的路径直接沿用，不为其增加重复任务回调。

共享正式入口位于 `common/scripted_effects/tca_military_council_task_effects.txt`；原版 `set_council_task`、`is_council_task_valid` 和 `councillor_task_target` 的实际用法分别参考原版 `events/relations_events/adultery_events.txt` 与军事任务定义。调用作用域、任务标记和省份目标的保存及清理约定，以该效果文件旁的说明为准。

### 军事内阁回归的借还隔离

即时用例需要王国级军制官署时，借用真实路职，以皇帝的一座非首府实县为测试主官治所。原路主保留自己的治所，避免县易主撤销寺院租约。军制来源必须是只领一路、契约与路类型相符的在任主官。借出前保存原任契约、路类型、主头衔、首府、领属、继承法与任命冷却；归还时先恢复头衔等级，再恢复领属，逐一核对借县的男爵领持有人。不得拆出额外的军制名额或改动原生上限。

跨日的迁廷、改制和主官死亡用例只借实县。改制用例按原版契约设置军制路主的军制子封臣；死亡继任只需文制州官，不给原生继任者附加军制契约。原路主继续持有路职、契约及全部封臣。测试在县级官署执行兵马监押的任免、任务接续与改制失格；主官死亡后核对实县的真实新持有人及旧锁。借前、借后和归还时分别核对皇帝直属军制人数与原生计数，归还原任冷却时扣除实际经过日数。准备不完整记为未执行，归还不完整记为失败。

### 自动化范围

原生断言覆盖资格与排他、普通任免规则、外部保护、补位与无候选、同署高职优先及过滤空池。任务用例检查训练指挥官的一般任务、提升控制力的省份目标、玩家新选择与目标失效；不将这些路径等同于四种任务的全部条件组合都已验收。

自然迁廷、武官死亡、主君死亡与改制通过对应原始入口触发并真实等待；其中主君更替检查保留锁的引用是否存活，以及原生撤销或按实际雇主重绑的结果。延迟用例使用独占 lane，不用直接清理效果替代自然路径。

正常任免权限须检查原生任免规则；直接效果成功不等于玩家界面允许操作。自然离廷、死亡与改制须等待原生处理，不能直接调用清理效果替代。主君更替用真实死亡检查旧锁清理及实际雇主重绑。不同头衔的继任者可以不同，不将王国继承人当作唯一宫廷雇主。

具体结果核对同一次冻结 `selection.json`、`terminal.json`、`result.txt`、`debug.log` 的 `TCA_TEST` 记录及 `error.log`；缺失、未执行或未确认观察者均不能视为通过。普通运行记录保存在仓库外，不在本页追加逐轮成绩。

### 尚待人工验收

以下均为待执行项。使用独立、可丢弃的调试局与存档，不在正常游玩存档测试。

1. **动态称号与提示**：准备不同层级的天朝地方官署，分别让三种差遣兼任军事内阁，再撤销差遣。检查内阁、任免列表和悬停提示中的称号与无差遣时的默认称号；模块保护应说明任职期间不可撤换，原版有期限保护仍显示原版日期。切换中英本地化与常用界面缩放，确认引用、文本与布局，并检查独立皇帝的中央内阁未受地方称号影响。
2. **真人任免与任务操作**：切换为地方主官玩家，按正常界面尝试撤换受保护军事内阁、撤销宫廷差遣并支付费用、指派差遣任务与内阁任务。检查正式差遣离任后有合格人选才补位，临时司马可按原版规则撤换；重新敕授后任务与目标衔接。补验管理禁卫任务的可用条件，不能以仿真 flag 用例代替真人路径。
3. **自然 AI 与跨署升迁**：准备具有入品资格且磨勘期届满的在任武官，让正常季度脉冲完成选拔、旧职撤销、迁廷和新职就任，不直接调用补缺效果。核对仅向总重要度严格更高的合格差遣迁转（含同职跨署）、原官署当季不连环补缺、两署军事内阁和任务状态正确，并持续观察 AI 招募、解聘及任务选择。仅单个回调通过不代表整段流转通过。
4. **保存重载**：分别保存正式差遣受保护、临时司马无模块保护、无人补位但任务暂存、主君死亡后次日重绑尚未执行的测试状态。重载后检查任免权限、任务与省份目标、快照清理和真实雇主重绑；目标已不合法时应回退默认差事。人工验收须记录实际准备出的状态，未准备出的分支仍是未执行。
5. **旧存档兼容**：以已有军事差遣、但尚无本模块内阁联动状态的旧测试存档副本加载，观察后续就任、离任及季度流转能否恢复一致状态。当前没有单独的旧档迁移入口，不承诺加载即补齐所有既有职位；是否需要迁移须由实际结果决定。
