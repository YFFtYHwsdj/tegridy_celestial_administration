# 原版覆盖与上游更新检查

## 用途与边界

通用检查入口：

```sh
python3 tools/check_upstream_overrides.py
```

2026-10-11 已移除旧司法专用兼容入口，统一使用上述通用检查入口。

检查清单位于 `tools/upstream_overrides.json`，其中每个 `overrides` 项记录原版文件、模组覆盖文件、对象 ID 和已审阅基线。脚本比较安装游戏中的原版对象与基线；若某覆盖还单独保留了未修改的原版逻辑（例如拘捕 trigger 的 `tca_judicial_arrest_native_common_valid_trigger`），也会核对这份副本。脚本不会要求完整覆盖定义等于原版，因为它们通常含有有意的模组改动。

脚本还会扫描模组与安装游戏 `common/` 下同类型、同名的顶层定义，以及 `events/` 下同 ID 的事件，包括 `名称 = { ... }`、`名称 = 数值` 和 `名称 = @[算式]`。对象类型按 `common/` 下第一层目录区分；普通子目录仍属于同一类型，`subject_contracts/contracts` 与 `subject_contracts/groups` 则分别处理。同名 trigger 与 effect 不算互相覆盖，文件内的 `@变量` 和事件文件的 `namespace` 声明也不算全局覆盖。

没有登记的同类型同名定义会报告出来，要求分类并登记，防止新增覆盖漏出清单。`known_extensions` 用来标记同名但只追加回调的 on_action；检查其原版和模组定义仍存在；可选 `baseline` 用于核对依赖的原版回调内容，未提供基线时仅检查存在性。追加定义本身不当作整段原版覆盖。

`auxiliary_extensions`登记`tools/`下独立、按需加载的辅助模组同名追加对象，要求记录原版、适配文件及已审阅基线。通用上游检查核对其原版基线和追加对象存在性；它们不属于普通模组的`common/`／`events/`加载范围，不计入下述普通查漏扫描的失效登记。当前仅登记CLI测试适配的开局回调，见[CLI测试说明](cli_game_tests.md)。

`file_overrides`登记整文件覆盖，当前为通判入口的`gui/hud.gui`及三关系标签的`gui/window_diarchy.gui`。通用检查逐字节核对完整原版与已审阅基线，并检查模组文件存在；缺文件报错，上游变化要求审阅，不自动刷新基线。独立查漏扫描仍只覆盖下述脚本范围。 file_overrides可用diagnostic_localization_keys显式登记被覆盖GUI引用的原版浮窗键，供check_test_run把无tca_、无文件路径的精确本地化错误归属到模组；目前仅登记DIARCHY_WINDOW_MANDATE_TOOLTIP，不会把所有原版本地化错误都判为模组问题。

## 独立覆盖查漏

单独检查登记是否完整：

```sh
python3 tools/scan_upstream_overrides.py
```

扫描先从模组和原版的实际定义发现同类型同名对象／同 ID 事件，再与人工登记比对。输出全部发现项的对象 ID、模组路径、原版路径和登记状态：

- `REGISTERED OVERRIDE`：已登记为覆盖。
- `REGISTERED EXTENSION`：已登记为追加定义；分类来自人工清单，脚本不自动判断追加语义。
- `UNREGISTERED`：发现同类型同名定义，但没有对应的登记。
- `STALE REGISTRATION`：清单中的对象／路径组合已不在扫描结果中，可能是文件移动、定义删除或原版改变。
- `SAME-PATH FILE`：模组与原版存在同相对路径的脚本文件。即使没有同名对象，也需单独审阅整文件替换造成的遗漏。

此入口不读取或比较基线文件，因此基线缺失、过时也不妨碍查漏；它不会写清单、生成基线或改变游戏文件。退出码 `0` 表示扫描范围内未发现待处理项，`1` 表示存在未登记项、失效登记或同路径脚本文件提示，`2` 表示目录／清单／源文件错误，扫描无法完成。同路径文件提示不会因登记了其中某个对象而自动消失，必须审阅整文件的加载影响。

可用 `--game-dir` 和 `--mod-dir` 指定目录；需要结构化输出时运行：

```sh
python3 tools/scan_upstream_overrides.py --json
```

独立扫描和上游检查复用同一套对象发现逻辑。前者回答“人工登记有没有遗漏”，后者回答“已审阅原版内容有没有更新”，并同时检查未登记的同名定义。新增覆盖时先扫描，再人工分类、登记和维护基线，最后运行上游检查。

扫描范围为 `common/**/*.txt` 与 `events/**/*.txt`。本地化、GUI、图形资源、历史数据、描述文件中的 `replace_path` 和其他模组的加载顺序不在当前自动检查范围内；扫描通过不能表述为所有类型的加载覆盖均已排除。

## 差异处理

- 退出码 0：所有登记覆盖的当前原版内容与已审阅基线一致；覆盖文件和已登记扩展存在；没有未分类的同名顶层定义。
- 退出码 1：原版与基线有差异、登记扩展缺失，或发现未登记的同名定义。查看逐 token 差异，先判断原版改变及模组适配，再更新模组逻辑和基线。
- 退出码 2：清单、基线或源文件缺失、不可读，清单字段缺失／类型错误，或脚本结构异常，无法确认结果。孤立的 `!`／`?` 和未闭合字符串不再被静默跳过；源文件解析失败时会显示文件路径。

基线保存在 `tools/baselines/`。审阅后手动更新对应基线；检查脚本不会自动写入文件或接受新原版内容。不要只更新基线来消除差异。

安装路径不同时可指定游戏 `game/` 目录：

```sh
python3 tools/check_upstream_overrides.py --game-dir "/path/to/Crusader Kings III/game"
```

此项是静态文本检查：忽略注释和空白，保留脚本 token、运算符与字符串差异。它不检查其他模组的加载顺序或冲突，也不证明引擎加载和游戏内行为正确；更新后仍需按相关模块文档做适用的游戏内验证。

## 回归验证

运行检查工具的测试：

- `test_check_upstream_overrides.py`：覆盖通用检查器的解析、基线比较、错误处理和只读性，另保留本地化 UTF-8 BOM 检查。
- `test_scan_upstream_overrides.py`：覆盖独立扫描的登记查漏、失效登记、同路径文件提示和只读性。

2026-10-11 已删除拘捕策略、身份评分和宫廷辖区三个业务测试文件，不再维护 P 脚本规则的 Python 模拟解释器或固定数值断言。业务行为按模块文档中的游戏内验收步骤验证；以下测试只验证工具及文件格式，不验证 CK3 引擎语义。

```sh
python3 -B -m unittest discover -s tools -p 'test_*.py'
```

2026-10-11 精简后本机静态验证：23 项测试通过；通用检查入口通过。独立查漏扫描发现 5 个已登记覆盖、14 个已登记追加定义，未登记定义、失效登记与同路径脚本文件均为 0。回归测试覆盖常量漏报、已登记常量／算式的漂移、算式运算符旁的空白与注释、跨类型误报、同类型子目录扫描、局部变量排除、损坏分词和错误清单的退出码，以及事件 ID 查漏、多 namespace 事件文件的基线比较与重复事件 ID 拒绝、缺失基线时独立查漏、失效登记、同路径脚本提示和只读性。验证使用临时样例，检查不会更新基线。

上述结果未包含引擎加载或游戏内行为验证。脚本只提取定义并比较文本，不是完整的 CK3 语法检查器，也不会计算算式或追踪引用依赖；特殊目录的对象类型划分仍需按原版定义方式确认。

## 官名本地化基线

中央名称初版的8个中英内阁名称键动态覆盖已撤销，避免法律展开动态文本时解析失败。用户随后确认接受显示不一致、不做额外兼容补丁，因此为统一卡片／法律名称新增的两个内阁对象覆盖、四个法律名称键替换及对应基线也已撤销。当前 `localization_overrides` 为空，撤销时保留原有5项脚本覆盖与14项追加on_action，后续新增2项命名覆盖后当前合计7项脚本覆盖。检查器保留本地化基线检查能力，只读比较，不自动刷新任何基线。脚本查漏扫描仍仅覆盖common/events，不自动发现未登记的本地化覆盖。


2026-10-11加载／命名修复新增`tgp_chinese_naming_tier_trigger`与`tgp_has_unique_chinese_naming`两个已登记覆盖。两者仅修正头衔作用域首府接口，完整基线取自本机1.20.0.4并经人工审阅；详细原因、兼容范围及待引擎验收见[头衔生命周期](judicial_title_lifecycle.md#2026-10-11-最新运行的加载与命名修复)。当前合计7个覆盖、14个追加on_action；基线检查不能证明真实升阶路径已无报错。
