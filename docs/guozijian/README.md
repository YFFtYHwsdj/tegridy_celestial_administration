# 国子监设计与接手入口

国子监是直属皇帝的中央教育官署，通过判监、七种直讲和两名行政属官组织人才培养。普通学生迁宫，仅持世族头衔者不迁宫；学生以原版教育、特质和正常科举成长，不另造学校经营或考试系统。

**本目录是交接设计，不是实现报告。当前尚未实施国子监，也没有制作探针、GUI或运行游戏测试。** 本次允许并进行了静态源码查找与文档检查；只有必须靠游戏测试才能确认的部分留在验证清单。接手者不得将源码中存在同名接口解读为完整学校行为已经成立。

## 如何阅读

第一次接手按下列顺序阅读，不要只读一页数值就开始写事件：

1. [完整玩法与制度](design.md)：先理解玩家能做什么、谁同意、何时付款、如何在学和离学、科举及任官如何交接。
2. [教育机制](education.md)：理解实际日数、季度、教师选择、各类收益与限额的算法。
3. [首版参数草案](balance.md)：集中给出费用、概率、经验、适性、AI和成长限额，以及完整年度的数量级例子。新增数值明确待确认，不能伪装成定案。
4. [接手实施说明](implementation.md)：原版与本模组实际文件、接口限制、状态归属、正式入口契约、实施次序和必须停手报告的问题。
5. [GUI方向](gui.md)：内阁中央官署、独立窗口、HUD入口、人物头像右键和权限；这里只描述，不制作原型。
6. [验证边界](verification.md)：只有静态不能解决、未来实施必须确认的项目；不是现在要求启动游戏的任务单。

完整机制以制度、教育两页为主，数字只在参数页维护，源码路线只在接手页维护。修改一个问题时同时核对它的上下游，不把同一份数值抄到几页形成多个真值。

## 如何区分决定状态

- **已确定规则**：用户已接受的玩法边界；改动需重新沟通，不因实现麻烦静默降级。
- **建议初版／待确认数值**：为使方案可实施而补齐的完整候选参数和小细则，允许审阅与调整，不是最终平衡。
- **静态已查明**：实际源文件里存在的对象、字段、调用上下文；不能外推引擎运行结果。
- **必须后续验证**：预算实际入账、迁宫后权限、共享超时所有权等，不能仅凭脚本文本证明。

招生年龄、考试结业、主动退学、异常学籍、中国单学校与两个新开局、教师自身特质只加成、迁宫失败先沟通等已经补充确认；不要继续把它们当成开放问题。皇族与差遣排除、无预装师生和真实首任候选也已确认；缺少专业教育特质的成年人必须作为边界安全处理。具体仍需用户确认的政策见[制度末节](design.md#十一仍需用户决定的少量政策)。

## 与其他模块怎样分工

- [官制](../court/README.md)与[任命](../appointment/README.md)：实际任官、入品与候选资格。无地地方主官仍是正式官员，招生不能漏排提刑、通判。
- [宫廷差遣与文武流转](../court_positions/README.md)：教职及待阙候选过滤；不另造一套流转系统。
- [科举](../examination/README.md)：原版AI活动与玩家代办的真实最终结果，学校只接成果与离学，不伪造及第。
- [官署经费](../office_funding/README.md)：财政与俸禄职责边界；学校拟接原生朝臣预算，不直接套地方辖区拨款。
- [官僚经验](../experience/README.md)：核对同人经验叠加；学校不授总督／牧守，不复制任职奖励。

三舍法、永久学校出身、免试、学校任官加分及资格图标全部暂缓。适当内阁任务可以后续讨论，不阻塞核心学校。
