# 主动交还兼领州县

## 状态与目标

本页是决议的规则、实现与验收边界主要维护位置。方案已批准，决议、次日交接、双语文本和原生回归已接入；主动交还两例已通过K=4定向引擎验收及同次日志核对；共用保存重载检查点仍失败，整体回归未全绿，界面与自然AI另待验收。伯爵级天朝官员主动交还超出的州县，复用[裁撤兼领](admin_rectification.md#三裁撤兼领规则)的继任选拔，直接另任官员，不经过皇帝或上级暂持。

该决议为现有[州郡兼领法](../court/local_domain.md)提供主动处理入口，不修改直辖计数、容量、超限惩罚、国家政策或任官门槛。它是自愿移交，不以皇帝或宰相的行政整饬权限为前提。

## 方案取舍

采用已确认的直接另任方案：复用现有候选资格、继承人优先、加权抽选及生成兜底，维持正常任官标准。先交上级再补授会造成临时超限并增加一次头衔转移，已不采用；另造一套选官规则会产生重复维护，也不采用。

办理单位为每次一个伯爵领。相较一次自动清空全部超额领地，这允许玩家明确选择放弃哪一处，并把失败限制在单次交接；代价是超额较多时需要重复办理。第一版不增加批量队列。

## 决议入口与资格

- 名称「交还兼领州县」，置于行政类决议。
- 本人为成年、存活、未被关押的有地天朝地方官员，最高有地实职为伯爵级；排除独立统治者、中央官署、家门、提刑、通判、奉祠与致仕身份。具体身份识别复用行政整饬及任职模块的正式判断，不按中文官名推断。
- 实际最高领主为独立天朝统治者；地方文官、军事长官均可办理。不强制国家采用某一档兼领法：只要实际直辖超限即可。
- 显示时要求存在额外可交还的世俗地方伯爵领；执行时还须实际直辖数大于当前上限。宽限期不妨碍主动交还，不必等税兵惩罚出现。
- 不在归正辖属、裁撤兼领或本决议的在途流程中；已申请奉祠／致仕者也须先结束原申请。相关流程开始及执行时应相互复验，不能只在决议侧单向设防。
- 不设金币、威望或影响力费用，不设置额外属性、官品、健康或性格门槛。不因一般战争、旅行而一概禁用；头衔确实不能合法移交时才阻止该目标，具体原生限制待实现前核对。

不能交还的州县应给出明确原因；不存在安全目标时不能执行。若超限仅源于额外男爵领，或主头衔与首府各占一个伯爵领而没有其他安全目标，本决议不处理，不为消除超限突破保留规则。

## 目标选择与保留范围

玩家进入决议后选择一个目标，确认前可取消；只有最终确认才开始选官及生成准备。

目标必须是本人持有的世俗地方伯爵领，并通过裁撤兼领的正式头衔判断。主头衔与领地首府伯爵领均保留；不得交还家门、无地官署、公国或更高头衔。选择器仅列出合法目标，确认时再次校验。

界面直接列出可交还州县的名称与纹章，不显示直辖数字；本次只交还一处，由朝廷另任官员接管。这里移交整个伯爵领及应随附的下属，不只是减少一个容量数字；提示不承诺精确减少一个直辖地产，实际变化依原生持有结构结算。

## 选官与交接

1. **确认当日复验**：本人资格、目标所有权、主头衔与首府保护、实际超限及在途互斥同时成立，才开始办理。保存本人、目标、当时最高领主和本次继任者，不依赖其他事件遗留的同名输出。
2. **复用选官**：在目标头衔作用域调用 `tca_admin_rectification_select_or_generate_successor_effect`，以当时实际最高领主为 `TOP_LIEGE`。先检查 `current_heir`，再按现有权重最多抽选三次，最后生成合格新官员；不得降低伯爵级任官门槛或改为私人指定继任者。具体候选规则只由行政整饬维护，本页不另抄数值。
3. **准备与占位**：只有本次显式成功标记成立才能接受输出；继任者进入共用预留机制，防止同时被另一项整饬或交还流程选用。生成兜底沿用当日准备家门与身份、次日接收有地头衔的时序。现有选官接口会检查预留标记，新的执行复验必须正确识别本单所有权，不能把本单继任者误判为被他单占用。
4. **次日执行**：重验本人仍存活、仍为同一政权的伯爵级天朝地方官、仍超限，目标仍由本人持有且不受保护；复核继任者的完整任职资格，尤其不能在等待期间已经取得其他伯爵级或更高实职。预留归属允许本单，其他资格不放宽。
5. **直接移交**：仅在新官员已安全具备接收资格时，由原持有人直接授予目标伯爵领。调用现有正式转移及任后状态维护入口，理顺政体、契约、主头衔、受任冷却和下属关系；不把皇帝或上级设为中转持有人。复用已核对调用契约的转移 effect，实际结算仍须引擎验收。
6. **确定新任官员的上级**：沿用裁撤兼领规则，优先归属同国、存活、天朝制且级别足够的法理上级持有人；无合格法理上级时直属最高领主。这里直属最高领主是新官员的封属关系，不是土地暂交最高领主。不得把新任伯爵留作原伯爵的同级封臣。
7. **完成**：核对头衔真实移交后，清理本单占位与在途状态，向本人报告交还的州县和接任者。保留原官员的主头衔、首府及剩余合法领地，不变更法理，不新增暴政、失地宣称、功绩、威望、影响力或好感奖惩。

没有审批、拒绝或讨价还价环节。次日执行是必要的任官准备；最终确认后没有另设撤回按钮；按后续文案要求，界面以交割行动表述，不罗列内部办理时序。玩家须在最初选择阶段保有取消入口。

## 失败、竞态与清理

- 本人死亡、被关押、改变政体／最高领主、升任更高级实职，目标易主或成为主头衔／首府，或超限已消除：本单终止，土地留在当前合法持有人处，不继续强行交还。
- 继任者死亡或失格：释放本单旧预留，按同一选官流程补选；涉及重新生成时重新等待一天，不能即时把有地头衔交给当日新建身份。为避免无限补选，每单最多补选一次，再失效即终止，之后可重新办理。
- 选官或交接失败：不得回落皇帝／上级暂持，也不得宣告成功；尚未转移的土地仍由原持有人保有。若头衔已经转移但任后善后失败，报告实际部分完成及诊断，不把它写成未转移，更不盲目逆向收回。
- 所有结束路径均清理本单在途状态及自己持有的候选预留；延迟事件重入或重复到达不得再次转移。清理不能删除其他流程后来取得的占位。
- 每单须有与现有整饬占位期限相容的超时清理及保存重载恢复策略。过期变量不能作为唯一清理机制；正常执行、前置失效与过期事件都应进入显式清理。跨日及重载所需状态存入可保存变量，不能仅依赖临时事件 scope。
- 生成后因失效未能授职的官员保留为合法待阙人物，沿用既有家门生命周期；不杀人或销毁其身份。限制在途单数与补选次数，避免失败循环批量生成人物。

上述是新增入口必须满足的设计要求，不表示现有裁撤流程已经逐项满足。现有自然裁撤链仍有[待引擎复测问题](admin_rectification.md#五自然裁撤链的回归边界)，复用前应核对；不得以新入口的静态检查把旧问题标成已解决。

## 玩家与AI规则

玩家每次自主选择一个合法目标；完成后若仍超限，可继续使用，无固定多年冷却。一次只能办理一单，等待时显示办理中及目标，不能重复确认。

AI每月检查一次，仅在满足全部资格、实际超限且无在途事项时启动一单，符合条件即办理，不另加性格随机拒绝。若有多个目标，随机选择一个合格的额外州县；避免未核实的收益或战略评分接口。后续月份仍超限时继续办理，直至不超限或无安全目标。第一版不作跨日连续批量交还、不增加全世界每日扫描。月度频率与随机目标按已批准方案采用，需自然AI验收其实际处理速度。

## 文案与界面建议

决议与通知以直接交割印信图籍表述，不写奏请、审批或等候朝廷选派。正常选官不足时生成合格接任者，只有资格变化或执行异常才中止，异常文本不描述为朝廷暂时无人可用；正文不显示直辖数字，确认按钮仅写「交还」。要求区显示超限与无待办事项，入口已过滤的底层身份资格仍然复验，但仅在不满足时展开，正常可用时不重复显示。

简中与英文同时维护，动态人物与头衔引用核对作用域及保存重载；不把主动交还写成惩罚性罢官。正式本地化仍需审稿和游戏内布局验收。

## 实现边界与入口

决议标识为 `tca_return_excess_county_decision`，新增入口和私有状态均用 `tca_` 前缀。在行政整饬所属文件或独立原生文件中维护资格、延迟交接与清理，避免将玩法写进测试工具。

复用现有选官、候选资格、预留、直接授地和任后维护；主动资格及失效判断单独封装，不通过伪造皇帝／宰相 `actor` 绕过旧互动权限，也不直接调用绑定强制裁撤书信上下文的执行 effect。若需抽出共用交接接口，应同步维护现有裁撤消费者，并只回归实际受影响路径。

目标选择复用原版 `decision_view_widget_select_realm_county` 与 `select_scope_object`，在决议页直接列出合法州县的名称和纹章。`setup_items` 以 `scope:actor` 为决议者，将本人持有且可交还的伯爵领加入 `item_list`；`is_item_valid` 再验目标，`scope:selected_item` 随隐藏确认事件传入正式起单入口。`default_item` 显式提供一个合法默认目标，供打开详情前判断可用性，未选目标提示由对应本地化键维护；玩家可改选。AI使用原生 `ai_select_item` 随机选合法目标；脚本直接触发确认事件时保留AI兜底。列表接口及原版同类代码已核对，实际显示与取消界面仍待验收。AI检查间隔的单位为月，`ai_check_interval = 1`。效果预览不展开选官与尚未建立的在途状态。不得为了实现该决议覆盖原版文件或顶层定义；若确有无法避免的原生同名接入，按覆盖规范另行登记审阅。

## 最小验收范围

两个主动交还用例已在K=4独立同局完整通过，7条断言全部通过、无跳过，观察者确认、完成标记和同次日志核对通过，无检出的模组相关引擎错误。覆盖正式确认事件消费列表选择、次日直接交接、首府保护、互斥、旧事件无副作用与失格补选。这个范围不能代替真实选择界面及自然AI验收。

合并行政整饬、退休资格和唯一保存检查点的范围中，共用保存重载用例有7项功绩断言失败，新增交还第45至47项通过。局部通过不构成共用检查点通过，功绩失败边界和复现条件见[当前复测状态](merit_verification.md#当前复测状态)。

- **资格与保护**：伯爵文武官可用；非天朝、独立者、公国级及以上、无实职、被关押者、未超限与在途冲突不可用；主头衔、首府及无地官署不能交还；只剩受保护目标时不强行转移。
- **正式流程**：通过正式入口选择一个额外伯爵领，跨真实一天后完成交接；核对原官员本职／首府、新官员政体／契约／上级、附属关系和直辖变化，确认最高领主与直属上级从未暂持目标。
- **选官覆盖**：优先扩展既有用例验证继承人优先、全国抽选、生成兜底；仅补新增入口的覆盖缺口。多名官员同时办理时不复用候选，不把等待期新获实职的人交成兼领官。
- **失效与清理**：目标易主或受保护、政权变化、不再超限、继任者失格与生成补选、重复到达、部分完成及超时清理；复用最少夹具覆盖有意义的正反与边界。
- **保存重载**：在唯一共用检查点加入最小待交接状态，核对续局完成或失效清理；不另建重复重载测试流水。
- **人工与自然AI**：专用测试局检查实际决议选择／取消／确认、双语提示与结果通知；观察AI每月启动、连续消化超额及不重复生成人物。直接调用 worker 不证明自然AI通过。

用例登记至行政整饬模块，按原生框架设置 `GROUP`、`EXCLUSIVE` 与 lane 清理；优先并行与私有对象，确有共享争用才独占。实现后先作最小静态检查，再把新增入口及实际受影响的裁撤路径合并为一次 `--parallel 4` 定向引擎运行；不因方案新增例行全量或串并行双跑。

- [死亡接入](../../common/on_action/tca_county_return_on_actions.txt)：原生 `on_death` 跨文件追加独立子回调，分类登记在[覆盖清单](../../tools/upstream_overrides.json)，不改原版基线。

- [唯一保存重载检查点](../../events/tests/tca_merit_saveload_probe_test_events.txt)：加入独立持久在途夹具、重载首帧只读快照、现场破坏和续局真实交接断言。为覆盖GUI真实保存等待，夹具独立构造在途态，把正式交接事件排至45日、预留延至90日；不改正式起单队列，不以此探针证明正常次日或31日超时链。正常次日路径由交还用例维护。
