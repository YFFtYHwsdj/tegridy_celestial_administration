## 通判／提刑选官共同规则

目标是让两职从同一文官体系中产生不同的专业侧重，保留原版功绩、仕途与政治经营的作用。两职分别使用独立的头衔继承法及任命类型，官职沿用既有对象与绑定，不修改普通地方文官或中央省部的评分。新法由官署维护安装，不恢复已废弃的提刑旧法。

两种任命类型均以原版地方文官 `celestial_civic_governor` 为完整基线，**除能力项替换和四项性格新增外，其余评分块整块原样调用，连同原版条件、数值、先后顺序一起保留**。不是仅从每块挑出几项；未满足原版条件的项目仍不生效。

### 资格与排序：两职均保留

- `level = merit`：保留原版功绩资格，不另设资源或功绩门槛。通判仍是伯爵级、提刑仍是公爵级，不为均衡候选人数改变官职等级。
- `allowed_candidate_tier = lower_or_equal`：保留原版候选官阶限制，不改成不限制官阶。
- `cooldown = yes`：保留原版任命冷却，不额外缩短或取消。
- 候选池与自然继任顺位仍由原生系统产生，不使用使命称职度或补位抽选自行重排。
- 保留现有专职资格、正常继任后校验、首次／纠错补位与历史角色排除边界。专职检查不能靠剥夺候选人的其他头衔来满足。

能力与性格是候选评分，不是功绩等级。原版概念文本记载先比较功绩等级，再比较候选分数；该排序尚待引擎复核，因此不能承诺较高专业分总能压过较高功绩等级。对比两职偏好时，应固定功绩等级与其他条件。

### 评分块一：通用基础分，全部保留

原样调用 `appointment_score_base`，包括以下各项，不因官职改为通判或提刑而删除：

- **威望与家族威望**：最高领主采用原版对应候选评分法律时，各按等级×10计分；沿用法律开关，不改成无条件计入。
- **家族传承与诗人志向**：`tgp_chinese_legacy_4` 的候选加分，以及家族志向允许时的诗人经验加分。
- **影响力等级**：通常为 `10×（影响力等级−1）`；保留推举继承环境的原版特殊分支，不把该分支强行用于天朝。
- **负面状态**：近亲繁殖、失明、无能或年龄相关病症的原版合并扣分（满足任一相关条件扣50，不逐特质重复扣）；被剥夺继承权−200、`gallivanter` −200、`devoted` 或神职的对应−250分支。
- **礼制判定的犯罪特质**：原版逐项检查的性偏离、乱伦、同性性行为、食人、弑亲、通奸等，按原版所属礼制是否视为犯罪判定，每个符合条目扣30。完整保留不等于新增清廉或赃罪系统。
- **目标头衔宣称**：强宣称+25、弱宣称+15，原版最高领主持有目标时的翻倍条件也保留。
- **出身**：低出身−25，原版最高领主持有目标时的四倍条件也保留。
- **关系及任职联系**：亲属、朋友、挚友及额外宫廷职位分支的条件完整保留；这些分支原本排除天朝持有者，不能概括为天朝亲属／朋友无条件加分。前辈+15、门生+10，以及候选是目标现任分权者时按天平加分等其他分支，也不主动删除。
- **计谋、决策与请愿**：诋毁−25、举荐+30；对应整合决策+30、家族辖区权利请愿+250、`oath_of_purge_pretenders_house` 家族修正+50，均保留原版条件及特殊继承环境分支。
- **性别法律与统治身份**：保留偏好／专属性别法扣分、独立统治者−1000，以及礼仪性领主在非最高头衔竞争中的−1000等分支。

这里的“关系”以原版 `scope:title.holder` 等实际作用域为准，不新增“对所辅佐知州的好感×系数”，也不把现任通判／提刑、知州和实际领主视作同一个人物。

### 评分块二：文官资历，全部保留

原样调用 `appointment_score_civic`：

- 心智不健全的原版合并判定：相关条件满足时−100。
- 最高领主允许功绩机制且候选有儒学教育时，按儒学教育经验÷4、取整及原版 `min = 5` 计算。
- `merit_civilian_career_score_bonus` 文官仕途加分。
- 庄园文官官署的四档候选加分，沿用原版参数与互斥分支，不换成中央大臣官署建筑。
- `ducal_conquest_perk` 对应的原版候选加分。

因此科举教育、仕途支持、家族庄园和相关生活方式能力都继续有效，不只留下能力与性格。

### 评分块三：地方回避，全部保留

原样调用 `appointment_score_celestial`：

- 王朝领袖的庄园所在地属于目标头衔法理辖区：−20。
- 与目标现任持有者或候选自身领主同王朝：满足原版任一条件扣50，不按两个关系重复扣。

无地官署是否满足这些条件，按实际法理、庄园与人物上下文判定；本设计不新写“改看绑定州／路”的回避算法。需要更细的监督对象回避时另行设计，不冒充本版已包含。

### 评分块四：治理经验与礼制关系，全部保留

原样调用 `appointment_score_governor`：

- 与自身领主交战：−9999。
- `governor` 特质：基础+5；经验达到25、50、75时各再+5，总计最高+20。
- 国家礼制（缺少时按原版回退至最高领主礼制）对候选礼制的敌意：依原版等级分别扣10、25或50。

### 评分块五：非军事任职表现，全部保留

原样调用 `appointment_score_non_military`：

- 有地候选人的首府 `county_holder_opinion` ×0.25并取整；目标现任是最高领主时再按原版翻倍。该项是首府伯爵领的持有者好感值，不是候选对知州的个人好感；无地候选不触发这一分支。
- 在目标现任持有者处担任内阁职位：+20。
- 在目标现任持有者处担任宫廷职位：+10。

### 任命类型内的直接项目：保留三项，调整一项，新增一项

- **年龄与退休，保留**：先判断原版退休条件，满足时按 `（当前退休年龄−年龄）÷2` 取整；否则40岁及以上+15、30岁以下−10，中间年龄不加减。保留完整原版判定，不仅复制一个年龄数字。
- **五星教育，保留**：外交、管理或学识五星教育任一满足时+10，不按教育类别重复累计。
- **虔诚等级，保留**：`10×（虔诚等级−1）`，等级1时不加减。
- **能力项，通判替换、提刑保持同权重**：通判把管理改为主要能力；提刑继续以学识为主并保留管理、外交。两职系数合计均为1，逐项按原版方式取整。完整公式各以[通判专用评分](../tongpan/appointment_design.md#专用评分)、[提刑专用评分](../judicial/appointment_design.md#专用评分)为唯一维护位置，不再额外叠加原版三项能力分。
- **性格项，两职新增**：仅增加公正／专断、勤勉／懒惰四项，分别使用两职设计页的权重；在最终修正前累加。这些特质通过原生能力值或其他原版条件产生的既有影响也仍保留，不从原版底座反向扣除。

### 最终修正：原样保留，仍放最后

最后原样调用 `appointment_score_final_factors`：保留扩张权力基础的三档加分及最低值处理，也保留礼仪性领主政体中支持请愿的×1.1／×1.15分支及全部适用条件。后者不能直接解释为宋朝官员普遍享有这两种乘数。

计算顺序为：五个共用评分块 → 年龄 → 本职能力项 → 五星教育 → 虔诚 → 本职新增性格项 → 原版最终修正。保留原版调用方式和数值上下文，不把最终修正前的分数缓存成另一套排序，也不把新增性格分放到最终修正之后。

### 明确不加入的中央专用项目

两职均不调用 `celestial_minister` 的中央专用评分：不增加运动领袖+100、执政运动成员加分、征服王朝优待文化+100、中央大臣专属庄园建筑、竞争政事堂时现任大臣+100，或中央按具体部门决定能力的分支。通判、提刑仍使用地方文官的年龄规则，不换成中央较轻的年龄修正。

完整保留地方文官底座，意味着第一版也保留虔诚、宣称、出身、诗人志向等不专属于监督官的原版因素。它们并非遗漏或默认关闭；若认为其中某项不适合两职，需要作为另一个明确的设计变更讨论，不能在实现时自行删掉。

## 任命分与履职数值

本设计只改变选官侧重。通判的任命分、忠诚度和使命称职度分别服务于选人、政治倾向和治理收益，不合并为同一个值；不因任命能力权重变化重算现有治理效率。提刑的任命分也不改变司法辖区、审批、拘捕和详覆权限。

官职重要性继续决定职位吸引力及调任比较，不当作候选人的专业能力分。首次／纠错补位须读取本职实际任命评分；正常继任继续交给原生系统，不以补位的加权抽选替换自然继任顺位。

## 第一版边界

不新增曾任某职、最低任职年数、荐举人、法学考试、清廉资源、赃罪记录、额外任期或年龄门槛。不把诚实直接视作清廉，也不把贪婪直接视作已有赃罪；本版只使用公正／专断、勤勉／懒惰四项性格。

这是一组初始平衡选择，不能据此宣称宋代存在相应量化选官制度，也不保证每次都选出称职或廉洁的人。

## 实现入口与验收

- `common/laws/tca_official_succession_laws.txt`：只允许官署标记头衔采用本职法，不作为领地法安装。
- `common/succession_appointment/tca_official_appointments.txt`：两职独立任命类型，完整调用共用底座、本职分与最终修正。
- `common/script_values/00_tca_official_candidate_values.txt`：共享年龄／教育／虔诚、本职能力与性格、提刑补位权重及原版冷却期限引用。文件位于根目录且提前排序；放在子目录时任命类型加载曾无法解析这些值，不随意迁回子目录。
- `common/scripted_effects/tca_official_appointment_effects.txt`：有持有人时幂等安装头衔法；提刑先清理废弃旧法。持有者的原版领地法仍由两职现有维护保证，家门法律不改；精确补位后仅对实际获任者补齐原生冷却，不缩短更长超时。
- 两职补位入口：先让挂靠上级在同次效果内暂持官署并安装本职法，再按正式 `appointment_candidate_score` 加权抽取，最低权重1；以 `granted` 精确授予选定者，避免 `appointment` 事务改用缓存继任人。有效现任不经暂持／抽取，不因缺少预览继任者而轮换。

### 原生回归与复核方法

原生任命超时同时服务于拒任、退休、考试和近期受任；`appointment_timeout_days` 是脚本读取入口，原版界面 `Character.HasNewAppointmentCooldown` 的日期计算也读取这项状态，但附带政体判断，不能只据其返回值代替天朝官员的超时断言。实际 `granted` 精确补位未自动取得近期冷却，因此仅在最终选定者获任后，通过原生 `set_appointment_timeout` 补齐 `NAdministrative.RECENT_APPOINTMENT_COOLDOWN` 定义的期限。已有更长超时不缩短，临时上级不设置，日常维护不续期；自然继任仍沿用任命类型的 `cooldown = yes`。

`events/tests/tca_official_appointment_test_events.txt` 中 `.1` 登记于通判模块，`.2` 登记于司法法律模块。每项自建候选与同持有人的临时原版文官参考头衔，当场销毁参考头衔与测试角色，直接比较引擎正式官职评分；覆盖能力取整、四项性格正反、复合资历与性格累加、本职法隔离及重复安装、补位权重下限与首次补位冷却，通判另查GUI评分不受抽取下限钳制、较长超时及重复调用的保护。

```sh
python3 tools/run_game_tests.py --case tca_official_appointment_test.1 --case tca_official_appointment_test.2 --timeout 600
python3 tools/run_game_tests.py --timeout 600
```

运行时核对同次冻结计划、终局、断言和引擎错误；同局全组需覆盖原有制度启停、补位、自然死亡和连续交接；通判生命周期另核对临时上级超时不变、最终官员取得原版期限及官署法，不以评分单项通过替代生命周期回归。新用例的普通地方参考头衔仍走原版类型；中央任命类型没有覆盖，中央真实候选、AI支持和界面仍需另验。

旧存档应在可丢弃副本中记录官署ID、持有者、旧法及家门法，再经过正式维护核对新法安装、旧法移除和身份稳定。新局重复安装不等于旧档迁移验收。通判已有名单与实际继任差异仍由[生命周期说明](../tongpan/implementation.md#未解决的生命周期一致性)维护，不放宽原断言。

冷却原生超时断言与界面getter不能混为一项：天朝样例中超时已设置时，该原版getter仍返回未显示冷却，实际界面展示保留待验收。实际分数浮窗、真实玩家／AI路径、长期任职、全部存档迁移和保存重载尚未验收。评分单项不证明这些项目通过，也不保证原版功绩排序与冷却在所有特殊情形中的行为。
