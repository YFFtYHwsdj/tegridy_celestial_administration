# 提刑官职头衔：原版与 mod 写法分析、当前实现

当前制度边界：提刑机构及本模组地方、中央司法审批由独立的地方司法制度法律启用，与因便／宋制官名选择无关。初始化、改制交接和待验收步骤见[官名与司法制度](court_system.md)。

2026-10-11 当前实现：1066 开局的 15 个文官路优先绑定固定无地头衔，其他辖区继续动态创建；已有有效绑定不迁移。固定机构与历史人物数据分开维护，详见 [1066 固定提刑机构](judicial_static_titles.md)。任命直接沿用原版天朝文官领地继承法，空缺与异常任职由既有补位流程修复，详见 [提刑任命验证](judicial_appointment_test.md)。下方标为历史记录的日志仅说明当时验证范围。

## 查阅结果

原版 `game/events/dlc/fp1/fp1_scandinavian_adventurer_events.txt:105` 在角色作用域使用 `create_dynamic_title`，得到 `scope:new_title`，随后设置无地、宣称及其他属性；授予持有者另用 `create_title_and_vassal_change` / `change_title_holder` / `resolve_title_and_vassal_change`。创建和授予是两个步骤。

AGOT 的 `2962333032/common/scripted_effects/00_agot_pirate_effects.txt:385` 采用同类流程。此例是临时海盗头衔，不是行政职位；其取得同级头衔后销毁的规则不适合持续存在的提刑官职。

TAO 的 `3343175673/common/scripted_effects/tao_game_start_effect.txt:54` 在贵族头衔重建时销毁旧头衔，再设置新无地头衔、历史和继承规则。它说明头衔属性、政府和继承是不同工作；不能把贵族家族继承套给提刑。

原版 `game/common/landed_titles/_landed_titles.info` 说明无地与若干销毁设置。`delete_on_destroy` 删除动态对象，而 `destroy_on_succession` 是每次继承撤销，不适合提刑。

原版 `game/common/on_action/_on_actions.info:104` 明确允许以 `on_actions` 链接独立效果。当前实现采用这种附加方式，不覆写原版 `effect` 块。

原版 `game/common/on_action/title_on_actions.txt:29` 规定：`on_title_destroyed` 的对象为 `scope:landed_title`，之前的持有者在 ROOT；不能误用头衔获取时的 `scope:title`。

## 当前实现

司法制度法律的全境维护在原生 `on_after_pass` 中执行，当日撤任及退出真实路法理树；启用时当日任命并挂回。`on_pass` 仅设置冷却，次日复核继续保留。修复前后复现及验收边界见[法律回调时序](judicial_law_tests.md#法律回调时序当前实现2026-10-15)。

### 适用范围

持有者为天朝政府且司法制度启用的有地王国级路：包括最高王国级的非独立文官主官，以及帝国／天下级独立皇帝持有的路。军事与都护契约仍排除。路须有持有人及可用首府；未创建或无持有人的路不设职。

同一符合条件的持有者如果拥有多个路，按各路头衔分别绑定。有效在任时提刑司法理上级为绑定路；停用、废置或销毁时退出真实路法理树，恢复后挂回原路。地方主官持路时实际隶属该主官，皇帝持路时实际隶属该皇帝当前可用且等级高于公国的刑部大臣，无可用刑部时暂隶属皇帝。换任、失去职位、被关押和获释通过原生回调维护；囚禁与释放先同步已有官署隶属，再请求次日完整维护。刑部取得职位也请求维护，覆盖保留刑部头衔的重新任职。原版囚禁会导致内阁空缺，释放不自动恢复职位；真正重新任职后恢复直属刑部。本次不实现旧存档迁移。

### 头衔对象

- 公国级无地头衔，不在地图上划县。1066 开局的指定 15 路使用 `d_tca_judicial_*` 固定定义；其他开局与未列入的辖区继续动态创建。
- 头衔命名为“某路名＋提点刑狱司”，继承路的纹章。
- 持有者称为“提点刑狱公事”，不附加路名；机构名仍带路名，与官员职名分开。
- 先设置引擎要求的首选首府县，再设置无地属性。优先引用路头衔首府，缺少时引用观察使的首府；两者都不存在则暂不创建。
- 首府字段仅用于引擎定位，不授予县，不创建官署建筑，也不赋予该县的收入或军队。
- 禁止自动宣称、王朝命名和游牧命名。
- 动态与固定官职均保留对象和所属路绑定。撤销时以 `destroy_title` 撤销当前持有状态，并退出真实路法理树；提刑司本身始终关闭 `delete_on_destroy`，恢复时复用原 ID。不设置继承即销毁。
- 持有者称号通过 `flavorization` 与 `TCAJudicialHolderTitle` 自定义本地化接入。仅检查主要头衔的本 mod 标记与路绑定；非提刑的普通天朝公国持有者回退原版节度使称号。配偶不获得提刑称号。
- 该桥接条目优先级为 28，高于原版普通公国称号的 27；其他 mod 的更高优先级条目可能覆盖，需要组合测试。
- 机构名仅为头衔显示名称，不创建官署建筑或部门系统。

固定头衔的历史文件暂未填写任职者；`holder = 0` 是待考数据占位，不是史实空缺断言。退出大厅后的维护仍按既有流程选任合格的非历史人物，无人可选时生成文官，建立家族、政府及直属路关系。因此本次并未提供大厅中可选择的历史提刑人物。未来补入历史任职者后，仍需验证其开局政府、专职资格和封臣关系。

### 绑定

路上保存 `song_judicial_title`，官职保存 `song_judicial_circuit`，后者带有 `tca_judicial_title` 类型标记。有效性检查要求双向一致。

使用 `tca_judicial_circuits` 全局列表记录本 mod 管理的路，以便清理已失去持有者或已转出适用制度的对象。普通维护只操作本 mod 绑定，不销毁其他 mod 的头衔。

### 生命周期

- 1066 固定机构的头衔历史声明所属路并建立引用；退出大厅后的维护先执行每存档一次的补接入口，再扫描相关领主。已有有效绑定直接复用，没有绑定时直接读取路上的固定对象备用引用，再回退动态创建。无人头衔历史效果是否在大厅执行仍待验证。
- 获得王国头衔或改变政府后，通过隐藏事件延迟一天检查，避免在变更中间状态处理。
- 路销毁：交接公职囚犯并撤销提刑任职，移出真实路法理树，保留官职对象、双向引用及登记。路恢复适用后复用原官职。
- 提刑官职被外部销毁：交接公职囚犯，移出真实路法理树并保留路绑定；路仍适用且未废置时，后续维护在同一对象上补位并恢复法理。外部模组主动删除对象不在本模组保证范围内。
- 每年对已登记路做失效清理，并扫描符合条件的路补建。
- 普通观察使换任：新持有者检查到已有双向绑定，复用原官职。
- 转出文官路或由不适用的持有人持有：按当前适用范围撤销官职；独立皇帝持路仍在适用范围内。

创建前验证绑定，重复运行不得生成第二个官职。销毁回调交接囚犯、维护持久标记并处理法理脱离，不递归销毁提刑司自身。空缺对象不重复执行持有状态的销毁事务。原生空上级写法未获支持，当前内部通过退役临时父引用脱离真实路；不宣称该字段为空值，具体实现、31项法理断言及保存重载边界见[本次验收记录](judicial_de_jure_probe.md)。

显式废置设置 `tca_judicial_disabled`，季度、年度与延迟官职维护均不补位；显式恢复清除此标记，在原对象上任命。路暂时失效不设置此标记，恢复适用时在原对象上补位。绑定存在不等于官职正在运行，任命与权限还检查制度、废置标记及持有者。

维护时恢复机构身份。15个已登记路使用稳定机构本地化键，显示时通过GetTitleByKey读取路名，因此改名不依赖临时scope；同一路的旧动态机构也复用这一键。其他自定义路继续使用set_title_name_dynamic，随维护更新名称，原生自定义文本可能仍产生缺键提示。

## 开发入口

角色作用域：`tca_refresh_character_circuits_effect = yes`，检查角色当前持有的路。

路头衔作用域：`tca_ensure_judicial_title_effect = yes`、`tca_restore_judicial_title_effect = yes`。

路头衔作用域的销毁和废置效果要求预先保存角色 `scope:tca_lifecycle_actor`；它是执行 `destroy_title` 的作用域，不获得官职。

在当前玩家为观察使的调试控制台中，可分别检查：

```paradox
effect tca_refresh_character_circuits_effect = yes
effect save_scope_as = tca_lifecycle_actor primary_title = { tca_abolish_judicial_title_effect = yes }
effect primary_title = { tca_restore_judicial_title_effect = yes }
```

这些命令仅供开发验证，不添加面向普通玩家的测试决议。关闭或卸载 mod 并不会自动执行脚本清理；本阶段不要把测试存档当作长期存档。

修改文件后需要重新启动游戏以加载脚本。新开局会自动检查；已有存档可以等年度维护，或在当前观察使角色下使用上面的维护效果进行调试。游戏中的头衔仍为空缺状态，因此不能以封臣列表中没有提刑人物作为头衔未创建的唯一证据。

必须在游戏内验证：

1. 开局确实创建无地主体，名字可正确解析；没有在地图上增加领地。
2. 重复运行维护以及保存后读档，不重复创建，空缺对象与双向引用仍存在。
3. 普通观察使换任不变更官职对象；没有遗留第二个官职。
4. 显式废置清理对象、双方引用与列表，年度维护不重建；恢复只创建一个。
5. 路被销毁、变为不适用政府、变成军镇或都护、成为独立领主时，年度或对应钩子正确清理。
6. 从角色作用域销毁尚无持有者的动态头衔可以正常执行；若引擎不允许，须调整为空缺头衔的实际可用表示，不能只删除绑定声称已经撤销官职。
7. 加入已有存档后，年度维护能补建；现有 mod 的 on_action 效果仍正常运行。
8. 待授予官员时，验证角色称号显示为“提点刑狱公事”，头衔仍显示“某路提点刑狱司”；普通节度使与配偶称号不得误变。
9. 待后续授予官员时，再验证政府、庄园、封臣关系和任命；不能把本阶段验收当作这些机制已实现。
